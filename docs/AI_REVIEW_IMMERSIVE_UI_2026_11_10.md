# 42.24.579｜AI 自动标注审核工作台 · 沉浸式批量审核 UI/UX

日期：2026-11-10

## 用户诉求与真实根因

- 审核必须从既有 AI 标注任务的“审核”入口进入；采用与单图标注台接近的全屏工作面积，并遮住左侧菜单和顶栏。
- 既有 `static/styles.css` 后段的三栏覆盖规则把页面固定为 176px 左筛选、中间网格、260～340px 右详情。1366px 下又强制压成两列，图片面积不足。
- 七项 KPI、筛选、标签映射、底部整批操作同时露出，视觉主次不清。
- `invalidateAiSelectionPreview60` 在勾选后调用 `patchAiAmbiguityPanel60`，导致歧义处理面板整体替换，可能引起焦点与布局跳动；图片卡片本身未必被重建。
- 图片与标注框使用同一图片显示区域计算坐标；如果仅为“统一裁切比例”改为 `object-fit:cover`，会引入目标框与原图不对齐的风险。

## 已实施的最小改动

1. 新增 `static/ai-review-immersive.css`，只作用于原 `.ai-review-page-shell`：用固定视口覆盖左侧导航，但保留 8px 四周留白、顶部返回与任务身份；既有任务路由 `#ai-review/{taskId}` 未改，离开工作台即卸载覆盖层。
2. 把审核内部三栏改为精简顶部、横向核心筛选、单独图片滚动区域、底部审核操作条。右侧图片检查改为点击图片后按需打开的抽屉；不另做单图精审平台。
3. 核心筛选显示“全部 / 有框·无歧义 / 有歧义 / 0 框 / 失败”；已修改、已转出、已拒绝、低置信度、困难候选收进“更多筛选”。所有旧筛选键、服务端数量接口和快捷操作均保留。
4. 图片卡片放入 `.ai-review-card-grid` 的纯布局容器。有歧义筛选时，原有 IoU、指定标签、自动模式与预检面板作为右侧独立工具区域；窄屏时自然移到图片上方。
5. 勾选、取消勾选、选择本页与全筛选冻结选择成功后，只清空过期歧义预检的反馈区域并更新选中数量；冻结全选状态明确显示筛选总数与已排除张数，不再替换整个歧义工具面板、图片节点及输入控件。
6. 原卡片及放大检查保留固有图像宽高比例，不使用遮挡裁切，降低目标框坐标偏移风险。
7. 详情抽屉、负样本转池、整批任务选项、单图编辑、诊断、分页及任务退出沿用原方法；整批任务操作继续是低权重折叠入口，选中入库为主要动作。
8. 本次没有修改 Python/FastAPI、CandidateStore、正式 GT、回执、版本校验、服务端冻结清单、数据库或原系统菜单。

## 交互边界

- 无歧义：按本页/全筛选选中，可跨页排除，原两次确认后使用 `commit_selected=true` 正式入库。
- 有歧义：先选范围，再按原 IoU 与保留模式预检，仅确认可处理的图片正式入库；无安全结果的整图跳过。
- 勾选不触发 `renderReviewPage` 或额外图片请求；翻页、筛选、提交成功后的有意义加载仍由原任务 Owner 管理。
- 浏览器刷新时，沿用原 `ai-review-route.js` 基于任务 ID 恢复，不创建额外独立功能入口；用户点击返回、切换其他主页面时沿用原关闭确认/退出机制。
- 旧版灰度与生产部署不受本地 CSS 改动影响，只有安装本版静态资源并刷新浏览器缓存后可见。

## 设计与适配

- 1920：图片网格根据可用宽度自动排列，详情不常驻占宽；有歧义时右侧约 282px 预检栏。
- 1366×768：恢复横向筛选和充足图片宽度；卡片最小列宽约 205px，右侧歧义栏约 252px；底部操作栏有界滚动，不覆盖图片。
- 768 及以下：筛选水平滚动；网格两列，歧义工具移到上方；选中与分页操作可换行。
- 不改变全站色彩变量、不引入组件依赖、不修改 `static/styles.css` 的历史规则；由末尾加载的局部样式覆盖本工作台。
