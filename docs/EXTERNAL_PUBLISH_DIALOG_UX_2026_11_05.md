# 畅联云算法训练平台｜新畅联模型交付弹窗与手动同步确认（42.24.536）

## 需求与实际语义

- 「算法列表 → 迭代版本 → 发布」不是全量同步算法主数据，也不是部署到硬件设备，而是把某个已训练版本的原始模型和已映射转换权重登记、上传并同步到新畅联。
- 「Version PUBLISHED」说明外部版本登记完成；「Weight PARTIAL」说明仍有部分权重待补充或待人工核验。两者不可混为「全部发布成功」。
- 当前版本已经有自动交付和失败恢复机制；本轮仅调整手动交互入口，不更改后台外部发布契约和存储审计。

## 42.24.535 原问题

1. 在算法版本行点击「发布」就先 GET 检查，并将原始权重/同步证据的长表格直接插入版本列表，破坏卡片布局。
2. 检查通过后直接 POST 外部发布，无独立确认步骤；读状态与执行写入混在一个点击动作中。
3. 技术信息（Artifact、Weight ID、OSS、SHA256、原始分类与读回证据）全部常驻页面，不适合业务操作。

## 42.24.536 改动

1. 算法版本入口名称改为「新畅联交付」，统一表示状态查询与手动同步。
2. 点击只打开**一层独立弹窗**并执行 GET 状态查询，绝不自动 POST。
3. 弹窗包含当前算法/版本、版本登记状态、权重已同步数、待人工核验数、逐权重短状态及可操作性提示。
4. 技术回执与类别证据默认折叠。原始后端详情无删改，可展开排障。
5. 只有预检通过且确需同步时，才能点击「确认同步到新畅联」发送 POST。
6. POST 结果无法确认时保留 uncertain 保护，后续只能「查询发布结果」，不得直接盲重试。
   即使 POST 已返回成功，若随后获取最新状态失败，也应等待读回，不允许直接使用旧状态重复 POST。
7. 删除在算法卡片中插入原始发布状态明细的行为；重启页面或切换算法不再产生对应额外内容。

## 不变的业务边界

- 远端 Version、Weight、OSS 的生成及身份核验仍由 `ExternalAlgorithmPublishService` 唯一处理。
- 仅训练成功且原始模型完整性校验通过、身份/存储/算力映射齐全时可发布。
- 失败或局部失败不能视为实机验证通过，不允许根据局部成功自动修正其他权重身份。
- 不涉及算法主数据同步、生产模型清理、正式 GT 与业务数据修改。

## 回归关注点

- 弹窗首次打开只有 GET；无确认按钮点击不得触发 POST。
- 不可发布状态显示具体修复建议，确认按钮禁用。
- 部分权重 UNKNOWN/UNVERIFIED/需管理员核对时，主信息简洁，技术详情仍可展开查看。
- 确认按钮只触发一次 POST；成功刷新状态与列表；结果不明时禁止自动重提。
- 动态宽度、桌面与窄屏布局、长文件名、列表滚动、关闭弹窗后数据不变。

## 验收声明

静态语法检查和浏览器测试用例更新不等于生产现场验收。真实新畅联接口、OSS 与设备侧仍须在可控环境逐一验证，不进行生产发布试验。
