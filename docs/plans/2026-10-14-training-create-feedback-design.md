# 训练任务创建反馈设计

## 目标

在不改变训练参数、后端协议和提交 Owner 的前提下，让用户能看见训练任务从本地校验到持久任务创建的真实进度，并在成功或失败时得到明确、可恢复的反馈。

## 设计

- `TrainingSubmitRuntime` 仍是唯一提交 Owner，原有九个真实阶段保持不变。
- 原阶段只投影为三个用户可理解的阶段：配置校验、素材核验、提交任务。阶段由真实代码路径推进，不使用模拟计时或虚假百分比。
- 点击后按钮立即进入原位 loading；反馈层作为当前创建弹窗内的状态面板，不创建第二个弹窗。CSS 延迟显现以避免快速请求闪烁。
- 成功只发生在 `validateTrainingCreatedResponse` 验证持久任务身份与队列状态后。成功文案明确为“已创建并进入队列”，不暗示 Worker 或 GPU 已开始运行。
- 本地校验或明确 HTTP 失败保留表单并允许返回修改。POST 后网络状态不确定时，不提供盲目重试，展示已规划任务 ID 并引导从任务列表核验。
- 所有反馈使用 `aria-live`、`aria-busy`，遵循 `prefers-reduced-motion`；1366px 与移动端保持按钮和状态可见。

## 验收边界

覆盖快速成功、慢速创建、明确失败、网络结果未知、重复点击、防焦点丢失与配置保留。截图只展示真实状态，不伪造业务进度。
