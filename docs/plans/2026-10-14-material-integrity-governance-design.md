# 重复与异常素材全局治理设计

## 目标

在现有素材 Full Audit、`DELETE_INDEX` 和 Durable MaterialBatch 上提供全局预览、冻结计划、二次确认与后台执行，安全治理同图同标注重复项，同时将冲突和异常留给人工处理。

## 领域合同

- 重复身份只接受完整 SHA256；同图同标注才进入自动建议，同图不同标注只允许逐组人工指定保留项。
- 源缺失、哈希漂移、无效图片或扫描未验证均不进入自动删除。
- 保留优先级依次为：历史/活动业务引用、源与哈希已验证、有效正式标注、正常状态、可追溯信息、稳定 Image ID。
- 同组存在多个不可删除引用时整组跳过；本轮不迁移 Image ID 或业务引用。
- 计划由服务端遍历完整审计结果生成，冻结项目、审计任务、素材 revision、标注 revision、组决策、保留项、删除项、跳过原因和确认凭证。
- 执行前再次校验 revision、当前哈希、标注摘要和引用保护；失效计划返回 409，不能部分发布。
- 执行创建现有 `DELETE_INDEX` MaterialBatch，使用同一个 Worker、选择清单、重试、取消和进度机制。共享物理源文件不删除。

## UI

Full Audit 总览增加“生成治理预览”；预览显示覆盖组数、建议删除数、冲突/保护/异常跳过数。用户确认后才创建后台任务。大量组不要求浏览器提交 Image ID；组列表继续分页。单组人工处理保留真实图片与 GT 框。

## 缓存与结果

终态沿用 MaterialBatch 刷新 Owner，并显式失效素材分页、训练素材摘要、标签适配、质量与当前审计状态。部分失败保持可见且可按现有任务机制重试。

## 最终实现说明

- 冻结计划存放在对应审计任务的 `dedup-plans/{plan_id}.sqlite3`，确认凭证只保存 SHA256；路径只接受 32 位十六进制计划 ID。
- 计划 API 返回统计与最多 20 组推荐，完整 KEEP/DELETE 清单只保留在服务端。大范围所选组通过临时 SQLite 表匹配，执行清单复用现有 `BatchSelection`，避免浏览器负载和 SQLite 参数上限。
- 历史保护覆盖训练/模型转换任务、活动 Prepare/标注/导入/清洗/批处理、Snapshot 以及算法/模型/评测记录。不能读取历史证据时拒绝自动治理。
- Worker 会把失效组标为失败并继续其他安全组；旧审计在任何治理任务进入终态后标记过期，必须重审才能再次生成计划。
