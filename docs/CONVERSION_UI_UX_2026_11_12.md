# 模型转换 UI/UX 轻量整理（2026-11-12）

## 目标与边界

在畅联云算法训练平台现有模型转换功能上做小范围可回归的展示改造，不新建一套任务列表、不迁移转换状态、不调整 Worker、SDK、API、数据库、GT 或产物事实。

参考：
- Azure Machine Learning：任务列表、服务端筛选、任务详情和日志分层；
- Ant Design：紧凑表格、次要操作收纳、稳定分页；
- GitHub Actions：运行日志与执行结果可追踪。

仅在唯一长期分支 `feature/external-algorithm-publishing` 修改代码；不部署 A800、4070，不操作服务或生产数据，不合并 `main`。

## 实施内容

### 1. 算法版本转换记录

- 维持原历史记录接口、服务端筛选、分页、轮询及任务 Owner，不新增请求和本页虚假筛选。
- 原有的状态选择器仍为唯一实际筛选状态；顶部快捷状态按钮仅当原状态选项存在时出现，调用原表单提交／筛选事件；未支持的状态不擅自生成。
- 列表由散列大卡片收敛为紧凑多列信息，统一行高、分隔线、标题、状态和按钮样式。
- 记录主操作为「查看详情」，下载和板端验证优先直接展示，非主要操作收纳到「更多」，复用原按钮和 onclick。
- 点击详情在同一个历史窗口内隐藏其他行、展开原记录参数/证据，并通过「返回转换记录」返回；不创建嵌套弹窗、不复制产物/执行数据；保留滚动位置和原按钮焦点。
- 状态概览保留原服务端投影，不再将本页任务数覆盖为全局或服务端统计值。
- 删除/停止/下载/日志等后端权限、行为及失败门禁均不变。

### 2. 新建转换

- 保留现有左主配置、右实时摘要和固定底栏；改为统一克制的浅色布局。
- 目标格式选择、输入、资源等主字段更清晰，非必填 CSC 等内容继续折叠。
- ONNX Opset、TensorRT 目标资源、Sophon 主配置及 RKNN INT8 校准继续留在主区，避免高级设置隐藏必填参数。
- 右栏不再暗示“数值检查自动通过”：仅提示后续真实图像／硬件验证。

### 3. 厂商与芯片管理

- 原 `conversion-catalog-runtime.js` 仍是唯一字典 Owner。
- 桌面端左侧厂商、右侧芯片能力表；窄屏回归为上下结构。
- 厂商主操作「查看」、芯片主操作「检测能力」；其他编辑、启停、删除收纳为当前行的「更多」，操作 ID、原删除/引用保护和 API 不变。
- 菜单展开在行内，不被可滚动表格裁切；操作后关闭菜单。原芯片能力显示、SDK 约束和资源错误继续保留。

### 4. 数值验证

- 质量中心原转换一致性模式和数值任务机制保持不变；记录中的原数值验证快捷入口继续复用。
- 明确区分“模型文件已生成”“离线数值比较”“目标硬件实际执行”“业务场景效果”，不以转换产物存在推断业务可用。

## 验证与风险

已检查本轮轻量模块、字典模块和新增 Node/Playwright 用例的 JavaScript 语法；本轮新增五项前端展示契约已通过隔离断言执行。**不能把语法或静态合同检查当作真实 Chrome 通过。**

当前工具环境不能 clone 远端仓库运行完整 Playwright、npm test 和真实 Chrome 截图；最终须以最新分支 SHA 的 GitHub Actions 和实际浏览器进行确认，尤其关注：

1. 1920/1366/768 三视口布局、表格横向溢出和菜单遮挡。
2. 原有转换记录状态筛选、分页、刷新、任务轮询、原始日志及完整证据可见性。
3. 同层详情返回、焦点、滚动位置及弹窗关闭后页面可滚动。
4. 厂商/芯片 CRUD 与引用保护；菜单内编辑、启停、删除仍按原合同执行。
5. ONNX/RKNN INT8/Sophon/Ascend/TensorRT 等转换配置和资源状态。
6. 模型数值验证与真实板端验证不能因 UI 变更失去入口。
7. 历史数据不完整或后端请求失败时显示真实状态，不自动宣称已验证。
