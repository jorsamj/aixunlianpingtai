# AI 自动标注审核｜已同意正式入库标识与防重复选择修复（42.24.582）

日期：2026-11-11

## 实际缺陷与改动范围

单图候选行通过 `commits` 回执表返回持久 `gt_committed`，既有 UI 会禁用单个复选框，但角标弱、筛选统计没有已入库数量；跨页“选择全部筛选结果”调用的服务端冻结枚举仍会返回已入库图，造成“勾选不能选但全选能选”的矛盾。此前“采用候选”与“正式 GT 已入库”视觉上也不够区分。

## 用户行为约定

1. 二次确认后沿用原 `commit_selected=true` 原子 GT 接口；仅凭提交回执与数据库 `commits` 判定“正式入库”，不根据客户端草稿采用状态伪造入库。
2. “全部”保留候选历史供审计；已入库卡片绿色角标与正文“已同意 · 正式入库”，复选框禁用，单图检查标识不可重复提交。更多筛选增加“已正式入库”。
3. 服务端按原冻结范围规则运行，只把 `commits` 中已入库 ID 排除出任何可操作冻结集合。冻结结果为 0 时不保留空选择，并说明“没有可选的未入库素材”。
4. 素材跨页冻结全选与排除按剩余未入库数据计算，仍保留分批正式 GT 入库、预检、请求回执和幂等处理。未选中素材与原 GT 均不修改。

## 验收

- `tests/unit/test_annotation_candidates.py`：真实持久提交记录下“全部”可查、已入库筛选可查、冻结集合全排除已入库、零框排除。
- `tests/frontend/ai-review-immersive-workbench.test.mjs`：UI 文案、标识、禁选、服务端筛选入口及已入库计数合同。
- `tests/browser/ai-review-api-roundtrip.spec.mjs`：隔离真实 API 正式 GT 写入 → 绿色标识 → 禁选 → 全筛选 0 张 → 刷新后仍存在 → 已入库只读筛选。

所有测试应以准确 Commit 的 GitHub CI 回执为准；未执行生产写入或部署。
