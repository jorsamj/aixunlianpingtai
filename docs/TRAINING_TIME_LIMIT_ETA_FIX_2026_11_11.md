# 训练最长时长与预计剩余时间修复（2026-11-11）

## 问题

1. 训练创建弹窗原先默认把未设置的最长训练时长渲染为 `0`，说明写着“0 = 不限制”；后端却仅接受 `0.1~720` 小时，导致创建失败。
2. 训练 Worker 把这个时长原样传入 Ultralytics 的 `train(time=...)`。Ultralytics 官方定义该参数覆盖 `epochs`，并在运行时按照时长重估总 Epoch，造成预计剩余时间随设定上限改变。

## 本次修改

- 表单：最长训练时长改为可选；留空或填写 `0` 都表示不限时；正数范围为 `0.1~720` 小时。
- 提交：在前端把 `0` 归一为 `null`；后端也兼容直接通过 API 传入 `0`，在校验和冻结任务参数之前转为 `None`。
- 训练：不再把最长时长传给 Ultralytics `time` 参数；继续以用户配置的 `epochs` 为主要终止条件。若设置了正数时长，使用批次结束回调执行独立停止上限。AI 追加训练共用同一时长预算。
- 进度：继续由真实 Epoch 耗时滚动平均（最近五个 Epoch）计算 `eta_seconds`；未产生可信 ETA 时显示“正在估算”，绝不直接用最长时长冒充 ETA。训练详情区分“预计剩余（按 Epoch）”与“最长训练时长（停止上限）”。
- 产物：保留既有训练结束、早停、质量门禁和模型校验流程；对时间上限触发的结束记录 `completion_reason=time_limit_reached`。
- 浏览器：更新相关静态脚本版本查询参数，以避免新旧前端逻辑混用。
