## 本批完成

1. **数据集素材翻页不再触发两次状态统计分页查询，附加的两次摘要统计也已合并。** 原 `material-pagination-runtime.js` 在页查询之外，另外发送两次处理状态 `limit=1` 分页查询；触发 `refreshSummary61` 时又发送两次全局总数/已标注 `limit=1` 分页查询。本批统一调用 `GET /api/v61/projects/{id}/materials/status-counts`：返回处理前、处理后、全局总数、已标注、标注框数和素材 revision。该请求不反序列化整页图片 JSON，不触发图片读取、外部请求或任务写入。
2. **同项目、同来源统计单飞合并。** 首屏素材页与摘要的同期调用复用同一个 Promise；普通素材页先展示真实当前页元信息，再异步补齐统计。统计读取失败时保留素材页、显示不可用标记和重试提示，不把失败伪装成零，也不覆盖较新的页面。切换存储源时旧来源数字不再短暂冒充新来源数字。
3. **跨请求复用可信统计。** 后端 `MaterialRepository` 在同一 SQLite 读事务内读取 revision 和聚合结果，按数据库路径、文件身份、revision、来源集合维护有上限的 128 项进程内缓存。跨实例/Worker 修改素材时 revision 改变，后续读取失效；失效只导致重算、不影响已提交记录。全局 `summary()` 复用这项聚合，减少首页/F5 重复扫素材状态及总量的机会。
4. **统计语义保留。** “处理前”包含 `unprocessed / pending_decision / cleaning`，处理后仅为 `processed`；两个标签数字只遵循存储来源过滤，当前页搜索、标签、标注过滤不改变两个标签代表的范围。全局素材总数/已标注始终覆盖全部来源，保持原总览口径。

## 42.24.402 追加：CI 浏览器契约纠偏

核对 `42.24.400` 的 48 个 GitHub Actions 工作流（44 成功、4 失败），失败日志来自以下已有行为与历史断言脱节：

- **Remote Conversion Runtime ×2**：打开转换弹窗仍向服务端请求最新页，但不强制整个部署目录重扫。将 Chrome 断言从 `forcedHistoryGets=1` 调整为 0，保留 `historyGets=2`、资源实时查询、预填输入尺寸和产物数据等业务断言。
- **Frontend Runtime Stabilization**：上传任务中心“清空已结束”现在只删除浏览器展示记录，旧浏览器用例仍等待服务端 DELETE 的异步 Promise；改为验证不删除服务器证据、旧组件销毁后不污染新实例。ZIP 404 已确认为失效显示记录时，不再提供会反复 404 的“查看任务”按钮，更新浏览器用例验证持久失效展示、停止自动重试及可人工恢复。
- **转换超时恢复**：真实核验路径是 `GET /deploy/jobs/by-request/{request_id}`，旧浏览器夹具只监听列表创建地址。新增精确的按幂等键查询拦截，并核对使用原始 `request_id` 且没有第二次 POST；没有修改或放宽真实超时与 UNKNOWN 业务逻辑。
- **ZIP Import Durable Runtime**：CI grep 守卫还要求旧 `uploadBatch(input)` 入口和上传中心直接删除服务器 ZIP。更新为要求显式 `.catch(reportUploadBatchError)`，并拒绝上传中心向服务器 DELETE；保留应用内经用户确认的正式导入历史清理操作。

本地完整前端 `npm test`：**1396/1396 通过**；ZIP `Permanent ZIP import guards` 原样运行（仅本地使用现有 Python 虚拟环境）**通过**；四个改动的 Playwright 文件语法检查通过。隔离环境缺少 Chrome，尝试安装 Chromium 时下载源返回 0 MiB 损坏包，故**尚无本地真实 Chrome 通过证据，必须以新 SHA 的 GitHub Actions 浏览器回归为最终门槛**。本追加没有改变生产上传、转换或任务处理代码；未部署生产。

## 仍待完成的 P0

1. **训练任务状态 GET 与旧任务调度解耦（高风险）**。目前 `list_jobs` 仍通过 `_v48_dispatch_training_queues` 处理部分 pre-Durable 旧任务，可能启动训练、迁移优先级；`sync_jobs_index` 仍可能写历史索引、补归档。`v53/bootstrap` 也会调用该投影。直接把逻辑删除会使旧队列在资源释放后永远无法继续，甚至破坏版本溯源。因此本批**没有修改**旧任务调度；在真实旧任务数量、生命周期及唯一调度所有者确认后，应独立建立维护/兼容调度执行边界，再把 GET 切至只读持久快照，并做断点/恢复/跨 Worker 验收。
2. **素材搜索/训练选择器大样本 SQL 与角色筛选**。分页已存在，`LIKE '%keyword%'`、大页码 OFFSET、role-page 的历史用量索引仍需相同筛选条件下采集 `EXPLAIN QUERY PLAN`、SQL 计时、结果一致性与磁盘 I/O，必要时局部优化，不凭猜测引入额外索引或第二套数据仓库。
3. **生产网络与外部资源检测采样**。素材缩略图、畅联云同步、转换历史和芯片能力的浏览器 `Stalled/Waiting`、反向代理、本机/远程探测尚待脱敏 HAR 与服务端同时间日志核对。不能把浏览器排队时间误认为服务端 SQL 时间。

## 发布与回滚约束

本批为纯 API/UI 和进程内只读统计缓存，无数据库结构迁移、无任务创建逻辑变化、不操作原始素材或正式标注。只允许以普通 fast-forward 推送到 `feature/external-algorithm-publishing`；不得合并 main、Tag、Release、强推或自行部署生产。验证未通过或发现跨来源统计不一致时，应通过普通 revert 恢复上一版本，并保留线上故障证据。
