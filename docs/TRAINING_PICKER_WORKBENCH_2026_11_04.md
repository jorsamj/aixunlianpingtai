## 需求与实现

- 页面展示范围与选择资格分离：GET列表、POST page/role-page保留历史与Test保护项；真正批选和最终训练准入仍严格执行原规则。默认不再将不可选素材隐藏。
- current_only包含当前与其他算法共同使用素材；other_only仍表示仅其他算法。
- 当前算法训练计数仅统计该算法真实消费证据任务，不混入其他算法或仅选入记录。
- Draft显式历史策略开关保留跨页选择，当前页不可用已选项允许移除，确认时提示；服务器最终准入兜底跨页过期资格。
- 单选与全选本页复用同一资格函数，Test未知/缺GT/保护不可绕过。
- 训练历史当前范围/其他范围、Train侧used/possible浏览采用原Task库索引与同一关系token UDF，不先Python遍历整库。Test状态、其他复杂历史仍保留原精确路径。
- deferred角色分页按批读取并执行原权威分类，不创建全量角色内存表、不算全库角色计数。正样本及两类负样本用原正式标签引用做必要条件SQL预筛，之后仍检查来源、几何、审核范围。无匹配positive不会逐图Python分类。pending_review稀疏/无匹配及深页仍有扫描风险，尚需增量角色投影治理，不宣称已彻底消除所有O(N)路径。
- AND/OR标签查询在原GT引用表实现，前端可检索名称/编码，每次最多渲染40候选，不改变已选标签事实。
- 池筛选传递算法身份；由原Pool表关联查询，旧全局成员不继承算法确认。
- 首批缩略图10张；后端物化失败返回503 THUMBNAIL_UNAVAILABLE，前端占位+单图重试，不自动下载原图。
- 原生单层工作区CSS：固定头尾、结果/筛选独立滚动、4/3/2列；主批量操作收敛，全量低频动作进更多。

## 2026-11-08｜素材数据获取与大范围冻结选择的定向修复（CI/现场待验）

- Word 任务书另列的 27,530 张批选超时、`/jobs` 缓慢、推荐配置和外部状态读取属于**独立性能专项**。本轮先核对原调用链，不把历史基线问题描述为已经复现的生产故障：`/jobs` 继续使用原 `sync_jobs_index(read_only=True)`；训练资源、推荐配置与外部算法预检已由 `training-create-hydration` 并行/有界加载，缺少生产 HAR、Server-Timing 和服务端实测证据时不重写任务真值或重复创建缓存。
- 实际发现的冻结路径风险：`selection-reference` 原按编号重复请求 role 页，每个有角色筛选的 deferred 页内部又从源数据首页开始扫描，形成大量重复读取；无角色筛选也使用逐页 OFFSET。现仅让冻结清单调用已有 GT 游标分页：每次顺序读取至多 1000 条，按**原同一 `training_material_role` 分类器**对角色筛选，仍使用必要的目标标签 SQL 预筛、原历史/池/GT 过滤与修订二次确认。选择清单内容、服务端冻结/任务提交/Worker 校验和 100 万条上限均不改。
- 另一处确定的范围错误：用户点击“全选全部可用素材”且旧批选接口返回超过 50,000 张时，前端引用回退旧代码错误地沿用当前 `sample_role`/存储来源等筛选，可能只冻结一个子集。现回退与旧全选请求保持同一“全部可用”语义：清空查询/标签/角色/附加筛选，只保留正式任务角色和历史策略；当前筛选的冻结仍保留原所有条件。不增加新 API。
- 原 `bulk-selection` 在 27,530 张时仍优先返回显式 ID；这是保留“可逐张移除”语义的既有合同。本轮消除该路径对 GT/历史复杂筛选先执行完整 `COUNT(*)` 的额外扫描：单次有界读取最多 50,000 条加哨兵行，不超限时以实际 ID 条数返回同样的准确 `total`，超限仍按原文案拒绝并由前端回退冻结。未经现场耗时与交互取舍验收，不把低于 50,000 的范围自动转为不可单张移除的冻结引用。该场景的**真实超时是否解决仍待现场核验**，不得把上述改进宣称为 27,530 张生产测试已通过。
- 补加 API 角色冻结游标/角色一致性回归、Node 全可用语义守卫和 Chrome 超限回退模拟。当前执行环境无 FastAPI/pytest/Playwright，后端/Chrome 实际测试留给准确 SHA CI；已能运行的 Node/编译/语法检查应单列实绩，不用模拟取代生产证据。正式 VERSION 未改，入口资源缓存键 `42.25.566`。无生产部署或正式数据、GT、Worker、训练资格变更。
- 原有 `MC_PERFORMANCE_DIAGNOSTICS=1` 白名单已包含 `/jobs`、训练资源和外部 readiness，但漏掉推荐配置与冻结选择/成员核验；本轮只补白名单及纯映射测试，默认诊断关闭时零额外扫描、零请求正文/SQL/身份记录。现场应按 endpoint、`Server-Timing`、响应字节、首次/温缓存与浏览器 Network 瀑布图分别记录，不得凭推测改动推荐配置、外部状态或 `/jobs` 的正式读取链路。
