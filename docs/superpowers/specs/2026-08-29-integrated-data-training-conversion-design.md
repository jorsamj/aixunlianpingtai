# 畅联云算法训练一体化闭环可用性设计

**日期：** 2026-08-29  
**状态：** 用户已逐节确认  
**实施路线：** 保留现有系统和数据格式，整合上传、清洗、标注、训练和转换五条核心链路

## 1. 目标

先在 Windows 本机形成可以真实运行和可验证的视觉算法训练闭环，再将同一套业务流程迁移到英伟达服务器及厂商转换环境。

交付后必须满足：

- 素材可真实上传和持久保存，刷新页面或重启服务后不丢失。
- 清洗执行真实图像质量检测，进度和结果可见，不停留在假“清洗中”。
- 人工标注和大模型候选标注均能生成持久化标注数据，并正确显示在缩略图和选材页。
- 训练任务能真实启动，支持自动随机试验集、手动训练/试验素材和版本迭代继承。
- 转换只在真实工具链可用时执行，无资源时快速给出明确配置说明。
- 所有主操作均有即时反馈、可恢复状态和可操作失败原因。

## 2. 范围和非目标

### 2.1 本次范围

1. 素材上传、批次预览、处理分流和持久化。
2. 图像质量清洗、结果确认和可恢复移除。
3. 素材搜索、状态筛选和大数量分页。
4. 标签集中管理、人工标注、自动候选标注和预览同步。
5. 训练选材、数据快照、随机试验集、版本继承、真实训练及报告。
6. ONNX、TensorRT、Atlas 和 RKNN 的资源检测、真实转换任务和产物校验。
7. Windows 本机闭环验收和英伟达服务器可迁移边界。

### 2.2 非目标

- 本次不整体重写前后端，不强制将当前文件存储迁移到新数据库。
- 未安装厂商工具链的 Windows 环境不会伪造 Atlas、RKNN 或 TensorRT 转换成功。
- 本次不引入无需的微服务或分布式队列；任务接口保持可替换，以便后续迁移服务器。

## 3. 统一业务状态

### 3.1 素材处理状态

| 状态 | 含义 | 所在分组 |
|---|---|---|
| `pending_decision` | 已上传，尚未决定是否清洗 | 未处理 |
| `cleaning` | 已加入真实清洗任务 | 未处理 |
| `awaiting_confirmation` | 检测完成，等待用户确认处理建议 | 未处理 |
| `processed` | 已确认清洗结果，或用户明确选择无需清洗 | 已处理 |
| `quarantined` | 用户确认移出正常素材，但仍可恢复 | 可恢复区 |

“无需清洗”与“是否已标注”互相独立。因此，未标注图片也可以进入已处理，但目标检测训练选材会将其排除并显示原因。

### 3.2 长任务状态

清洗、自动标注、训练和转换统一使用：

`queued -> running -> awaiting_confirmation/succeeded/failed/cancelled`

- 任务状态必须持久化，页面刷新后重新查询服务端。
- 前端轮询每次都渲染新状态，不得在终态时保留旧的“执行中”弹窗。
- `failed` 必须包含可读原因、失败阶段和可重试范围。

## 4. 素材上传与数据一致性

### 4.1 上传批次

- 每次单张或多张上传都生成 `upload_batch_id`。
- 文件完整写入后再原子更新索引；文件或记录任一失败时不返回假成功。
- 上传结果弹窗显示本批全部图片，但采用分页或虚拟渲染，不一次创建数千/数万个 DOM 节点。
- 每张图片可设为待决定、需要清洗或无需清洗。支持当前页和当前搜索结果的批量设置。
- 未决定素材继续保留在未处理，关闭弹窗后可从上传批次继续处理。

### 4.2 防止刷新丢失

现有后台索引任务可能持有旧的素材列表，并在上传完成后将旧列表整体写回，导致新素材记录被覆盖。改造要求：

1. 同一项目的索引修改使用共享串行修改器。
2. 修改时读取最新索引，只合并当前操作负责的记录和字段。
3. 索引使用临时文件、同卷替换的原子写入方式。
4. 索引带修订号；读取后发现修订变化时，放弃旧快照并重新合并。
5. 缩略图、标注摘要和质量索引任务不得整体覆盖素材列表。

## 5. 真实数据清洗

### 5.1 检测项

- 无法解码或文件损坏。
- 内容完全重复和感知近重复。
- 清晰度异常。
- 过暗、过亮或信息量过低。
- 尺寸、长宽比或通道异常。

检测结果包含问题类型、度量值、阈值、建议和可预览对象，不仅返回“合格/不合格”。

### 5.2 两阶段流程

1. 系统扫描并持续更新已扫描数、异常数、当前阶段和耗时。
2. 扫描完成后自动进入结果确认页。
3. 用户可对单项或批量选择保留、标记异常或移入可恢复区。
4. 系统不在用户确认前自动删除原图。
5. 单张失败不得导致整批永久卡住；任务记录失败项并允许仅重试失败项。

## 6. 搜索与大数量性能

- 搜索范围覆盖当前项目全部素材，“未处理/已处理”是附加筛选条件。
- 匹配字段包括文件名、英文标签、中文名称、素材处理状态和标注状态。
- 前端对输入做延迟触发，服务端做过滤和分页，页面仅渲染当前页或可见区域。
- 批量操作必须在执行前显示作用范围：当前页、已勾选项或当前搜索结果。

## 7. 标签与标注

### 7.1 标签管理边界

- 标签的新增、英文代码、中文名称、改名、禁用和删除统一放在“配置中心 -> 标签管理”。
- 标注页只能选择已有且可用的标签赋给标注框，不提供标签新增、改名或删除入口。
- 标签筛选和标注选择均来自同一份标签库数据。

### 7.2 人工标注

支持标注框创建、选择、移动、缩放、更换标签、删除和撤销。保存时：

1. 验证标签存在、坐标有效且不越界。
2. 原子写入正式标注文件和标注摘要。
3. 前端从服务端重新读取已保存结果，再显示成功。
4. 同步刷新素材大图、缩略图和训练选材弹窗的标注叠加层。

### 7.3 自动候选标注

- 大模型配置放在配置中心，支持火山、千问、OpenAI 兼容接口和本地模型。
- 模型配置可绑定提示词模板、预期返回格式和标签映射。
- 自动标注首先产生候选标注，只有用户确认后才写入正式标注。
- 返回格式错误、坐标非法、标签不存在、超时或模型失败时，不写入部分损坏标注，并保留可诊断日志。

## 8. 训练选材与数据快照

### 8.1 选材可见性

- 选材卡片在缩略图上显示标注框、英文标签和中文名称。
- 已处理但未标注的图片不可用于目标检测训练，页面明确说明排除数量和原因。
- 启动前检查图片可读、标注可解析、标签映射完整，且训练集/试验集数量有效。

### 8.2 试验集模式

**默认自动模式：**

- 用户选择一批已标注素材并设定试验集百分比。
- 每次创建任务时生成新随机种子，所以连续任务的抽取结果可以不同。
- 将种子、训练素材 ID 和试验素材 ID 写入任务快照，保证单个任务可复现。

**高级手动模式：**

- 用户分别选择训练素材和试验素材，系统不再随机拆分。
- 两组素材不得重叠，且都必须通过启动前检查。

数据集构建以任务快照中明确的 `train_image_ids` 和 `val_image_ids` 为准，不再因素材库的历史 `split` 字段而丢弃用户已选素材。

## 9. 真实训练和版本继承

### 9.1 版本起点

- 算法首个版本从用户选择的母模型或初始权重开始。
- 后续迭代默认从该算法“最新成功且权重可读”的版本开始。
- 最新版本失败或权重缺失时，系统显示可用的上一版本并要求用户确认，不静默回退到母模型。
- 任务快照记录父版本、权重路径与摘要、数据清单、训练参数、环境和随机种子。

### 9.2 启动反馈

- 点击后按钮立即进入提交状态并防止重复提交。
- 成功时显示任务编号、排队/运行状态和详情入口。
- 失败时在当前弹窗内展示具体原因和修复建议，不只使用短暂消失的提示。
- Windows 本机首先完成真实 CPU/CUDA 小型训练闭环。英伟达服务器沿用相同快照和报告格式，只替换执行资源。

### 9.3 报告

- 算法整体报告展示各版本指标趋势、数据变化、父子版本关系和可用产物。
- 单版本报告展示数据快照、参数、指标、曲线、混淆矩阵、日志和产物。

## 10. 模型转换和资源可见性

- 转换弹窗先返回短期缓存的资源状态，并在后台刷新真实检测，避免初次检查导致长时间白屏。
- ONNX、TensorRT、Atlas、RK3588 和 RK3568 分别显示可用、缺少组件或不兼容。
- 缺少资源时显示组件名称、版本要求、配置位置和验证结果。
- 只有真实编译器或转换 SDK 可用时才启动对应任务。
- 任务保存排队、转换、校验、成功或失败状态，以及模型文件、校验信息和完整日志。
- Windows 首先完成 ONNX 真实转换和加载校验；其他格式在对应工具链环境执行。

## 11. 页面整合原则

- 五条核心链路每类操作只保留一个正式入口和一个最终处理器。
- 停用互相包装、覆盖和通过 DOM 监听器修补旧弹窗的兼容层。
- 页面按钮具备待机、提交、成功和失败反馈。可恢复任务的进度必须来自服务端。
- 标注缩略图叠加层共用同一个渲染器，素材库、上传批次和训练选材不各自实现不同规则。

## 12. 错误处理与恢复

- API 错误使用统一的错误代码、用户可读消息、开发日志摘要和可重试标记。
- 弹窗内的校验或提交错误保留在弹窗内，直到用户处理或关闭。
- 长任务记录最后心跳或进度时间；服务重启后对未完成任务做恢复、失败定性或重试，不无限保留“运行中”。
- 移除素材首先进入可恢复区，真正永久删除不在本次默认清洗动作中。

## 13. 验收与测试策略

实施遵循“先复现失败、再修复、最后回归”，测试在独立项目或临时数据副本中运行。

### 13.1 后端与数据测试

- 单张/批量上传、刷新、服务重启和上传/后台索引并发。
- 无需清洗状态迁移，包含未标注图片。
- 真实损坏、重复、近重复、模糊、明暗和尺寸异常样本。
- 标注坐标、标签映射、原子保存和刷新重读。
- 任务快照、自动/手动数据划分、随机种子可复现和父版本选择。
- 转换资源缓存、真实工具链拒绝和产物校验。

### 13.2 浏览器闭环

- 上传 -> 本批缩略图 -> 分流 -> 清洗确认/已处理。
- 画框 -> 保存 -> 刷新 -> 缩略图和训练选材可见。
- 搜索文件名、中英文标签和状态。
- 创建训练任务 -> 配置试验比例 -> 启动 -> 显示任务编号或可操作失败。
- 打开转换 -> 立即显示资源概况 -> 执行可用格式或明确告知缺失项。

### 13.3 真实运行验收

- 使用小型真实数据集在 Windows 完成一次 CPU 或 CUDA 训练，生成可加载权重、指标和单版本报告。
- 基于上述成功版本再运行一次迭代，校验父版本和实际起始权重。
- 至少完成一次真实 ONNX 转换，并用独立加载器或推理运行时校验产物。
- 在数万张素材项目中验证搜索、批量弹窗和转换资源弹窗不因全量 DOM 渲染或同步扫描卡死。

## 14. 实施顺序与模型选择原则

具体实施计划在本设计复核通过后单独编写。实施优先级为：

1. 数据持久化和并发安全。
2. 上传分流、真实清洗、搜索和标注闭环。
3. 训练快照、试验集和版本继承。
4. 自动标注兼容层和真实转换资源。
5. 全链路、性能和 Windows 真实运行验收。

对实施辅助模型的选择，数据并发、标注几何、训练继承、任务恢复和转换校验等高风险任务优先使用强推理与完整验证；样式整理、机械性检查和重复测试可使用较轻量模型。无论使用何种模型，交付门槛和验收证据保持一致。

## 15. 完成定义

本设计不以“按钮可点”或“接口返回 200”为完成。只有第 13 节中的独立数据、浏览器闭环和真实运行验收均通过，且没有已知的高优先级无反馈、数据丢失或假产物问题时，才可宣布一体化闭环完成。
