# 畅联云算法训练 Windows P0 闭环设计

日期：2026-08-28  
状态：已确认设计，待实施计划  
适用版本：v42.14.0 及后续兼容升级

## 1. 背景与目标

当前平台已有素材、标签、标注、清洗、自动标注、算法资产、YOLO/Paddle 训练、算法版本、训练报告和模型转换等实现基础，但后端 `app.py` 与前端 `static/app.js` 长期叠加多代 API 和覆盖函数，造成按钮无响应、多个页面状态不同步、声明存在但真实链路不稳定等风险。

本设计的第一阶段目标是在 Windows 本机形成可重复验证的 P0 闭环：

1. 平台稳定启动并恢复历史数据。
2. 标签库成为素材筛选、人工标注、自动标注和训练类别的唯一权威来源。
3. 单图、多图和 ZIP 上传后都进入统一的本批次处理流程。
4. 清洗、无需清洗、人工标注和自动标注真实改变后端数据。
5. 算法创建、展开版本和训练入口真实可用。
6. 版本迭代默认使用最近一个可用算法版本权重。
7. 训练质量、单版本报告和算法综合报告读取真实数据。
8. 所有关键按钮具有明确反馈并纳入浏览器回归。
9. 为第二阶段 NVIDIA Linux/CUDA 部署保留跨平台边界。

## 3. 总体架构策略

采用“增量替换、唯一实现、闭环验收”，不进行一次性全量重写。

### 后端

将新增或重构逻辑收敛为可独立测试的服务边界：

- 标签 Schema 服务：标签规范化、使用量、启停、重命名和 class_id 重排。
- Annotation 服务：坐标校验、原子写入、摘要生成和缓存失效。
- 素材工作流服务：处理状态、上传批次、清洗确认和级联删除。
- 算法资产服务：算法 CRUD、版本排序和迭代基础模型选择。
- 模型提供商适配层：火山方舟预设、兼容视觉 API 请求和响应解析。
- 报告服务：版本报告与算法综合报告使用各自数据口径。

现有 API 在迁移期可以保留兼容入口，但同一业务操作只能有一个正式实现。兼容入口必须调用正式服务，不得复制业务逻辑。

### 前端

对本次触及的业务按职责增量拆入 `static/modules/`：

- `api.js`：统一请求、错误结构和超时。
- `state.js`：当前项目、标签、素材、算法、任务的规范化状态。
- `modal.js`：弹窗栈、关闭最上层和 Toast。
- `labels.js`：标签管理与标签选择数据源。
- `materials.js`：素材卡片、筛选、批量模式和导入批次。
- `annotation.js`：标注编辑器和原子保存结果同步。
- `cleaning.js`：清洗任务、进度、确认和最小化。
- `model_config.js`：火山/API 配置和提示词模板。
- `algorithms.js`：算法 CRUD、版本展开和报告入口。
- `training.js`：训练弹窗、快照、迭代基础模型和任务状态。
- `quality.js`：数据质量图表。
- `reports.js`：单版本与算法综合报告。

旧 `static/app.js` 保留应用引导和未迁移业务，但受影响模块的旧 override/hotfix 必须删除或失效，禁止双重事件绑定。

## 4. 标签与素材状态模型

### 4.1 标签 Schema

标签库是唯一权威来源。每个标签至少包含：

- `id`
- `code`：英文标准标签，如 `fire`
- `display_name_zh`：中文对照，如 `明火`
- `status`：`active` 或 `disabled`
- `color`
- `shortcut`
- `created_at`
- `updated_at`

规则：

- 训练、annotation、YOLO 类别、提示词和部署均使用 `code`。
- 中文只用于界面展示，不参与类别身份判断。
- 素材筛选、人工标注下拉和自动标注标签选择只读取 `active` 标签。
- 素材标签多选使用 OR 逻辑。
- 标注编辑器不得创建、删除或重命名全局标签。
- 修改英文编码时必须原子更新 annotation、class_id、素材摘要和质量缓存。
- 正在使用的标签删除前必须阻止并返回使用量；停用不破坏历史 annotation。

### 4.2 素材双状态

处理状态：

- `unprocessed`：尚未完成清洗决策的原始无标注素材。
- `processed`：清洗保留、明确无需清洗或导入时已有有效标注。

标注状态：

- `unannotated`：无有效框。
- `partial`：存在候选或未完成确认的标注。
- `annotated`：存在已确认且合法的正式框。

两个维度独立保存，不通过 `annotated` 布尔值推断全部业务状态。

### 4.3 未处理与已处理页面

- 未处理页面不显示标签、检测框或标签筛选。
- 未处理页面提供“批量清洗”和“批量无需清洗”。
- 批量模式提供全选、反选、取消选择。
- 已处理页面从标签库生成筛选项，使用图片卡片和每页 48 张的分页。
- 训练只允许选择 `processed` 素材。

## 5. 上传与清洗

### 5.1 上传

统一入口为“上传素材”，支持：

- 单张或多张 JPG、JPEG、PNG、WEBP。
- ZIP 数据集。

任意上传完成后均打开“本次导入素材”窗口，显示本批次卡片并提供：

- 全选
- 反选
- 无需清洗
- 批量清洗

ZIP 使用后台任务并显示上传、校验、解析和导入四个阶段。窗口最小化后任务继续运行。

### 5.2 清洗

清洗采用两阶段提交：

1. 扫描阶段只产生问题列表与建议，不删除文件。
2. 用户确认后才级联删除选择的图片、annotation、摘要、缓存和索引。

传统图像算法为默认实现：SHA-256、感知 Hash、Laplacian、分辨率、解码验证和亮度统计。任务必须记录状态、进度、当前阶段、已用时间、ETA、错误、开始时间和结束时间。

## 6. 人工标注

人工标注支持多矩形框、新建、选择、拖动、四角缩放、标签切换、删除、撤销、重做、缩放和平移。

保存使用单次原子操作：

1. 校验图片存在。
2. 校验每个标签在标签库中且为可用状态。
3. 校验坐标为有限数值，满足 `0 <= x1 < x2 <= width`、`0 <= y1 < y2 <= height`。
4. 写入临时文件并原子替换 annotation。
5. 生成 `labels`、`box_count`、`annotation_status` 和缩略图预览框。
6. 将有有效框的素材标记为 `processed`。
7. 使当前图片相关质量缓存失效。
8. 返回完整、规范化的素材对象与 annotation。

前端保存成功后只替换当前素材对象，使素材卡片、缩略图、大图预览和标注窗口立即一致。刷新后必须从磁盘 annotation 恢复相同结果。

## 7. 本地与在线模型自动标注

### 7.1 适配方式

采用“统一候选标注协议 + 多提供商适配层”。第一阶段支持四类真实接入：

1. 火山方舟视觉 API 预设。
2. 阿里云百炼/千问视觉 API 预设。
3. 本地 OpenAI 兼容视觉服务，例如 vLLM。
4. 本地 Ollama 视觉服务。

火山预设默认使用：

- Base URL：`https://ark.cn-beijing.volces.com/api/v3`
- API 形态：Chat Completions 或 Responses 的兼容视觉输入
- 图片输入：Base64 data URL
- 鉴权：Bearer API Key

千问预设使用阿里云百炼的 OpenAI 兼容地址、视觉模型和结构化输出。具体模型名与工作空间地址由用户配置，不在代码中写死会过期的模型版本。

本地 OpenAI 兼容服务通过 Base URL、模型名和可选 API Key 接入；本地 Ollama 使用其原生图片输入与 JSON Schema。平台不负责在普通配置流程中自动下载大型模型，避免未经确认消耗磁盘、显存和网络；模型服务由用户或部署人员先行准备，平台负责发现、连接测试和调用。

若用户已有普通检测模型 HTTP 服务，后续可以增加 `detector_http` 适配器，但其返回仍必须转换为统一候选标注协议。

### 7.2 模型配置

模型配置包含：

- 配置名称
- 提供商预设
- Base URL
- 模型或推理接入点名称
- API Key 引用
- 请求超时
- 重试次数
- 最大并发
- 默认自动标注配置
- 启用状态
- 能力声明：图片输入、JSON Schema、最大图片大小和并发能力
- 最近连接测试结果、延迟和测试时间

Windows 使用 DPAPI 或 Windows Credential Manager 保存密钥；Linux 第二阶段使用环境变量或 Secret 挂载。API 返回、普通日志和前端接口永不返回完整密钥。

创建或编辑配置时必须支持“测试连接”：用户选择一张测试图片和提示词，平台展示脱敏请求摘要、原始响应、解析后的候选框和耗时。测试不得写入正式 annotation。

### 7.3 提示词模板

模板支持以下受控变量：

- `{{labels_json}}`：允许的英文标准标签及中文说明。
- `{{image_width}}`
- `{{image_height}}`
- `{{business_instruction}}`
- `{{output_schema}}`

平台提供检测框 JSON 默认模板，用户可以在配置中心编辑业务说明。模板预览必须显示最终发送文本但脱敏密钥。

提示词模板与模型配置分离并版本化。同一模型可以绑定多个业务提示词；任务记录所用模板 ID、模板版本和最终标签列表，保证问题可追溯。

### 7.4 返回契约

模型候选结果规范化为：

```json
{
  "boxes": [
    {
      "label": "fire",
      "confidence": 0.93,
      "x1": 120,
      "y1": 80,
      "x2": 410,
      "y2": 360
    }
  ]
}
```

服务端必须校验 JSON、标签、坐标、置信度和重复框。非 JSON、未知标签、越界坐标、401/403、429、超时和服务异常都按图片记录明确错误。整批允许部分成功，但总结必须显示每张失败图片。

模型结果只进入候选区。用户逐图确认或进入人工标注编辑器修正后，才写入正式 annotation。

### 7.5 自动标注任务体验

- 普通模式只选择标签、素材和提示词模板，默认模型由配置中心指定。
- 高级模式可选择模型配置、置信度、并发数、超时、重试和是否覆盖同标签旧候选框。
- 正式批量执行前默认抽取少量图片预览效果；用户确认后再跑全部图片。
- 进度显示成功、无目标、解析失败、接口失败和待确认数量。
- 候选框可以批量接受、逐图拒绝或进入人工编辑器修正。

## 8. 算法资产与迭代训练

### 8.1 算法 CRUD

“创建算法”只调用正式算法资产 API，后端校验名称唯一性并返回完整算法对象。前端局部追加，失败显示服务端原因和建议。

算法列表每行可展开版本；训练入口位于算法行。训练任务页面只展示进行中与历史记录，不重复提供创建入口。

### 8.2 迭代基础模型

选择顺序：

1. 从算法版本按训练完成时间倒序查找。
2. 选择最近一个真实存在且可加载的 `best.pt`。
3. 没有 `best.pt` 时允许使用可加载的 `last.pt`，并明确提示。
4. 最新版本记录无可用权重时，回退到更早的最近可用版本并提示原因。
5. 历史版本均无可用权重时才使用母模型。

任务记录：

- `base_version_id`
- `base_version_name`
- `base_model_path`
- `base_model_kind`
- `base_selection_reason`

### 8.3 训练快照与真实执行

训练弹窗只能选择已处理素材。任务开始时锁定训练与试验图片 ID、标签 Schema、每标签数量和 Snapshot ID。

训练参数必须真实传入 Worker。训练前验证环境、数据 YAML、基础模型和标注；训练后验证 `best.pt` 或 `last.pt` 可加载。缺少环境、CUDA 不可用、模型不存在或训练没有产物时明确失败，不制造模型。

## 9. 数据质量

数据质量弹窗包含：

- 综合质量分与评级。
- 标注完整度、标注有效性、标签均衡度、重复控制、分辨率质量和样本覆盖度雷达图。
- 图片、已标注图片、未标注图片、检测框、标签、重复样本、异常框和低分辨率 KPI。
- 每标签数量柱状图。
- 面向业务用户的简单建议。

指标必须由当前选定训练/试验素材计算，不得使用与训练快照无关的全项目假数据。

## 10. 两层训练报告

### 10.1 单版本报告

每个版本报告包含：

- 一句话结论。
- Precision、Recall、mAP50、mAP50-95、总 Epoch、最佳 Epoch、耗时和图片数量。
- mAP、Precision、Recall 与各类 Loss 的 Epoch 趋势。
- 逐标签指标。
- TP、FP、FN 和混淆矩阵。
- 由模型预测与人工 Ground Truth 比较产生的漏检、误检样本。
- Snapshot ID、训练/试验图片、标签数量和每标签数量。
- 基础版本、模型、全部训练参数、Seed 和资源。
- 阶段门禁记录。
- best/last 和转换产物状态。

### 10.2 算法综合报告

算法整体报告包含：

- 算法档案。
- 总训练次数、达标次数、未达标次数、总时长和平均时长。
- 各版本核心指标趋势。
- 历史累计标签与检测框数量。
- 最佳版本。
- 当前版本与上一版本对比。
- 每个版本到其单版本报告的入口。

两类报告使用独立 API 与数据模型，禁止将算法汇总数据伪装成单次训练数据。

## 11. 模型转换与部署产物

模型转换采用“统一中间模型 + 厂商真实编译器”的流水线：

1. 从算法版本的真实 `best.pt` 或 `last.pt` 导出 ONNX。
2. 校验 ONNX 可加载、输入输出名称、动态/静态形状和推理结果。
3. 根据目标硬件调用对应厂商 SDK。
4. 校验目标文件真实存在、非空，并记录工具版本、命令、日志、哈希和来源版本。
5. 有目标硬件时执行板端或服务器推理验证；仅转换成功但未上板时标记“已转换，未实机验证”。

### 11.1 Huawei Atlas / Ascend

- 真实工具：CANN ATC。
- 输入：经过校验的 ONNX。
- 输出：`.om`。
- 配置：`soc_version`、输入形状、精度和可选量化参数。
- 验收：ATC 退出码成功、OM 文件存在，并在可用 Atlas 环境执行最小推理。

### 11.2 Rockchip RK3588 / RK3568

- 真实工具：RKNN-Toolkit2。
- 输入：经过校验的 ONNX。
- 输出：`.rknn`。
- 配置：明确选择 `rk3588` 或 `rk3568`，不得将一个芯片产物冒充另一个芯片产物。
- INT8 转换必须绑定代表性校准数据集及其 Snapshot ID；FP16/INT8 能力按芯片和模型支持情况展示。
- 验收：Toolkit2 构建成功、RKNN 文件存在；有开发板时通过匹配版本的 RKNPU Runtime 或 `rknn_server` 执行最小推理并对比输出。

### 11.3 NVIDIA

- 真实工具：TensorRT。
- 输入：ONNX。
- 输出：`.engine`。
- 产物必须记录 TensorRT、CUDA、GPU 架构和精度，避免跨环境误用。
- 在目标 NVIDIA 服务器上执行反序列化和最小推理后才能标记“已实机验证”。

### 11.4 转换资源和失败规则

转换任务绑定具体转换资源。资源检测结果包括 SDK、版本、支持芯片、GPU/NPU 和最近检测时间。缺少 ATC、RKNN-Toolkit2 或 TensorRT 时任务明确失败，并给出安装位置与解决建议，禁止生成占位文件。

同一算法版本可以存在多条转换记录；每条记录保留源模型哈希、目标硬件、转换参数、校准 Snapshot、工具版本、日志、产物和验证状态。

## 12. 交互与错误处理

关键按钮审计范围：

- 创建算法
- 展开版本
- 开始训练
- 查看数据质量
- 保存标注
- 上传单图/多图/ZIP
- 批量清洗
- 批量无需清洗
- 删除素材
- 模型转换
- 下载产物
- 关闭最上层弹窗

每个按钮必须有唯一事件处理器，并产生以下一种可观察结果：打开正确弹窗、发起正确 API、改变真实状态、下载真实文件或显示明确错误。

统一错误结构：

```json
{
  "ok": false,
  "code": "ANNOTATION_SAVE_FAILED",
  "message": "标注保存失败",
  "detail": "标签 fire 不存在",
  "solution": "请先在配置中心创建 fire 标签"

```

子弹窗关闭时只关闭栈顶弹窗。

- 前端显示后端最终选择的数据目录和持久化状态，便于诊断升级后空数据问题。

- 完成 GPU 训练、推理、重启恢复和产物下载实机验证。

## 14. 测试与完成标准

### 测试层级

1. 单元测试：标签映射、坐标校验、版本选择、报告计算、API 返回解析。
2. API 回归：真实文件落盘、状态同步、级联删除、错误结构和密钥脱敏。
3. 浏览器回归：关键按钮、弹窗栈、局部更新、刷新恢复和控制台错误。
4. 端到端：上传 → 清洗/无需清洗 → 标注 → 数据质量 → 算法 → 训练 → 版本 → 报告。

### 隔离要求

测试使用 `MC_TRAIN_DATA_DIR` 指向临时或固定测试目录。除只读兼容性检查外，不允许自动化测试写入用户现有生产数据目录。

### 完成证据

- 上传后素材真实存在并显示。
- annotation 保存后文件变化，刷新后框仍存在，缩略图和预览一致。
- 清洗确认只删除用户勾选项并级联删除 annotation。
- 创建算法后立即显示，重启后仍存在。
- 第二次训练任务记录正确的基础版本和真实权重路径。
- 最小训练产生可加载权重、真实指标、算法版本和单版本报告。
- 算法综合报告显示真实历史趋势。
- 火山 API 未配置、鉴权失败、限流、超时或返回错误时明确失败；合法返回形成候选框并经确认后写入。
- 无厂商转换 SDK 时明确失败，不生成目标格式占位文件。
- 有真实转换环境时，Atlas 产生可校验 `.om`，RK3588/RK3568 分别产生目标匹配的 `.rknn`，NVIDIA 产生与目标环境匹配的 `.engine`。
- 转换记录可追溯源算法版本、ONNX 哈希、SDK版本、参数、校准 Snapshot 和实机验证状态。

## 16. 同类平台调研结论与采用原则

### Ultralytics Platform

其官方流程将上传、标注、训练、导出/部署放在一个工作空间中，并以数据是否具备训练条件展示 Ready/Not Ready。采用原则：平台首页和训练入口应告诉普通用户“下一步缺什么”，而不是只堆参数和按钮。

### Roboflow

其数据版本是冻结的时间点快照，训练可明确选择以前的 checkpoint；自动标注先在小样本上测试类别描述和阈值，再运行全批次。采用原则：训练 Snapshot 不随素材库变化；自动标注先预览后批量执行；续训来源必须可见。

### CVAT

其自动标注要求先把模型标签映射到任务标签，并允许阈值、ROI、取消任务；质量体系使用 Ground Truth 与预测/标注比较。采用原则：标签映射在任务开始前完成，自动结果可取消，质量和错误样本必须基于 Ground Truth。

### Label Studio

其 ML backend 把模型预测作为 pre-annotation，允许人工接受、拒绝和修改，而不是直接当作正式标注。采用原则：本项目统一使用“候选标注 → 人工确认 → 正式 annotation”。

### 本项目不照搬的部分

- 不引入复杂的团队计费、积分和云资源市场。
- 第一阶段不扩展分割、关键点、OBB 等任务类型，先确保矩形目标检测闭环稳定。
- 不把多个竞品的导航全部拼进菜单，普通模式只保留完成当前任务需要的入口。

## 17. 已确认决策

1. Windows 本机 P0 先于 NVIDIA 服务器实机部署。
2. 最新版本无权重时回退到最近可用版本；历史均无权重时使用母模型。
3. 自动标注采用兼容视觉 API 适配层，并内置火山方舟预设。
4. 模型结果先作为候选标注，经校验和用户确认后写入。
5. 标签库为唯一来源，英文为标准身份，中文为对照展示。
6. 算法报告分为算法整体综合报告和单版本训练报告。
7. 采用增量模块化与闭环验收，不做一次性全量重写。
8. 第一阶段不自动迁移当前非空业务数据目录，目录统一另行使用显式、可回退的迁移流程。
9. 自动标注同时支持火山方舟、阿里云百炼/千问、本地 OpenAI 兼容视觉服务和本地 Ollama。
10. 转换采用真实 ONNX → 厂商 SDK 流水线，并区分“已转换”和“已实机验证”。
