# v42.25 Training Data Contract Consolidation Design

日期：2026-09-11  
状态：IMPLEMENTED ON `refactor/v42.25-runtime`, NOT MERGED, FULL REGRESSION NOT VERIFIED

## 1. 目标

v42.25 第一批不增加新业务功能，目标是修正训练前的数据合同，使训练任务面对重复素材、负样本、历史标注和多来源采集时具备确定、可解释、可追溯的行为。

核心目标：

1. 同一内容不得跨 Train / Validation / Test 泄漏；
2. 同一内容存在多条素材记录时，必须先判断 Ground Truth 是否一致；
3. Ground Truth 冲突必须在训练启动前阻断；
4. `confirmed_empty` 必须作为正式负样本，而不是未标注；
5. Annotation Scope 必须进入权威标注和训练快照；
6. Snapshot 必须锁定当次训练的真实数据含义；
7. 历史数据升级不得清空、移动、重新编号。

非目标：

- 不重构 Task Runtime；
- 不优化 ZIP / YOLO 大规模导入性能；
- 不修改 GPU 资源策略；
- 不重构算法资产与版本仓库；
- 不处理畅联云账号体系；
- 不提升正式版本号。

## 2. 数据权威关系

### 2.1 Material

Material 表示“训练平台可引用的物理/逻辑素材记录”。

Material 可以重复指向相同内容，因此：

```text
material_id != content identity
```

`content_sha256` 才是精确内容身份的主要证据。

MaterialRepository 可持有标注摘要字段，用于：

- 搜索；
- 分页；
- 筛选；
- 训练候选选择；
- 页面统计。

但这些字段只是 projection，不是 Annotation Ground Truth authority。

### 2.2 Annotation Ground Truth

AnnotationRepository 是正式标注权威源。

正式标注合同：

```text
image_id
annotation_state
annotation_scope
boxes
content_digest
version
```

状态语义：

```text
unannotated
    尚未确认 Ground Truth

annotated
    已确认，至少存在一个正式框

confirmed_empty
    已确认，在 annotation_scope 所描述的类别范围内没有目标
```

## 3. Annotation Scope

### 3.1 为什么需要 Scope

单纯 `boxes=[]` 无法区分：

```text
没有人标过
```

和：

```text
已经明确检查过但没有目标
```

也无法表达：

```text
已确认没有 cigarette，
但并不代表已经检查过未来新增的 fire / helmet 等类别。
```

因此正式负样本需要：

```json
{
  "annotation_state": "confirmed_empty",
  "annotation_scope": ["cigarette"],
  "boxes": []
}
```

### 3.2 Scope 规则

新数据：

- `annotated`：优先保存显式 scope；没有时可从 box label/code 推导；
- `confirmed_empty`：应尽量保存明确 label code；
- `unannotated`：scope 必须为空。

历史兼容：

- 历史 `annotated + boxes` 且 scope 为空：从 boxes 推导；
- 历史 `confirmed_empty + boxes=[]` 且 scope 为空：兼容为 `['*']`；
- `['*']` 表示“历史全局确认范围”，仅用于兼容，不建议新工作流主动产生。

### 3.3 Digest

Annotation content digest 必须覆盖：

```text
annotation_state
annotation_scope
boxes
```

改变 scope 即改变 Ground Truth 语义，因此必须改变 digest / version。

## 4. Duplicate Preflight

### 4.1 基本定义

针对本次被用户明确选择的素材，先按 `content_sha256` 分组。

#### Case A：same SHA + same normalized GT

```text
A content_sha256 = X
B content_sha256 = X
A GT == B GT
```

行为：

- 选择稳定 canonical material；
- 其他 material 仅从本次训练 Snapshot 中排除；
- 不删除 MaterialRepository 中的重复记录；
- Snapshot 写入 duplicate audit。

原因：

- 同一张物理图片重复训练没有价值；
- 删除源记录是数据治理行为，不应该由训练切分隐式完成；
- 历史订单、来源、任务、审计可能仍需这些 material_id。

#### Case B：same SHA + different normalized GT

行为：

```text
duplicate_annotation_conflict
```

必须在训练启动前失败。

禁止：

- keep first；
- keep latest；
- 随机选择；
- 自动合并不同框；
- 静默覆盖；
- 等 YOLO 已启动后再报 content leakage。

后续应建设专门 Conflict Preflight / Resolution UI，但第一批不实现 UI。

### 4.2 Normalized GT 比较

稳定 label/code 优先于 class_id。

原因：

- `class_id` 可能随着历史 label array / snapshot mapping 改变；
- `label/code` 才是业务稳定语义。

规则：

```text
if label/code exists:
    compare stable label/code
else:
    fallback class_id
```

框坐标比较覆盖：

```text
x1, y1, x2, y2
```

以及：

```text
cx, cy, w, h
```

浮点值规范化后再计算 digest，避免 JSON 字段顺序等非语义差异造成误冲突。

## 5. Inseparable Component

### 5.1 为什么不是单一 group key

旧实现只从多个来源字段中选第一个非空 group key。

这无法表达传递关系：

```text
A 与 B 属于同 group
B 与 C 属于同 video
```

正确结论应该是：

```text
A / B / C 必须作为一个不可拆分 Component
```

因此使用 Union/Find 语义构建 Component。

### 5.2 当前 Component Relation

精确内容/文件身份：

- `content_sha256`
- normalized file identity

显式来源组：

- `group_id`
- `video_task_id`
- `source_group_id`
- `near_duplicate_group_id`
- `sequence_group_id`

摄像头采集：

优先：

- `camera_session_id`
- `capture_session_id`

没有显式 session key 时：

- `camera_id + session_id`

禁止仅使用：

- `camera_id`

因为单摄像头可能运行数月，仅凭 camera_id 会把大量独立采集全部绑定为一个超大 Component，导致比例无法切分。

### 5.3 未来近重复

当前只预留 `near_duplicate_group_id` / `sequence_group_id` relation。

未来近重复算法如果启用，应该在训练切分前把近重复检测结果固化为 group relation，再由 Component 系统统一处理，而不是在 split 后单独补检查。

## 6. Split Pipeline

v42.25 第一批后的目标流程：

```text
Exact user selection
    ↓
Load authoritative annotations
    ↓
Normalize annotation semantics
    ↓
Duplicate SHA preflight
    ├─ same GT → canonicalize
    └─ different GT → conflict / stop
    ↓
Build inseparable Components
    ↓
Component-level Test selection
    ↓
Component-level Validation selection
    ↓
Train remainder
    ↓
Final leakage guard
    ↓
Immutable Snapshot
```

### 6.1 Independent Test Mode

用户显式选择独立 Test 素材时：

- 同一个 SHA 不得一份出现在 Train selection，一份出现在 Test selection；
- 即使 GT 完全相同，也必须拒绝；
- 原因是用户已经明确赋予不同角色，系统不能通过 canonicalize 悄悄改变试验合同。

### 6.2 Random Test Mode

从训练池随机抽 Test 时：

- 先构建 Component；
- Test 按 Component 选择；
- 再从剩余 Component 选择 Validation；
- 不允许同一 Component 被拆开。

### 6.3 Final Guard

即使 Component 逻辑已经防止泄漏，仍保留最终 `_assert_no_leakage`。

这是 defense in depth，不得因为“前面已经做了 Union”就删除。

## 7. Confirmed Empty / YOLO Negative Samples

合法负样本：

```text
annotation_state = confirmed_empty
boxes = []
annotation_scope != []
```

训练 bundle 输出：

```text
images/.../image.jpg
labels/.../image.txt
```

其中 label 文件为空。

这是 YOLO 正常的负样本形式。

禁止：

- 为负样本制造假框；
- 把 confirmed_empty 改成 annotated；
- 因为空 txt 就删除图片；
- 把 unannotated 当 confirmed_empty。

## 8. Training Snapshot v3

新 Snapshot schema version：

```text
3
```

每个 image record 必须锁定：

```text
image_id
role
dataset/source provenance
component/group identity
content_sha256
storage reference
annotation_state
annotation_scope
annotation_hash
box_count
labels
```

Snapshot 总体还需要记录：

```text
ids
counts
requested split settings
actual ratios
seeds
label schema
label counts
negative_scope_counts
excluded_duplicate_ids
duplicate_groups
```

### 8.1 为什么 Snapshot 锁 annotation hash

训练后如果用户再次编辑标注：

```text
历史训练任务不能被“重新解释”为使用了新标注。
```

因此 Snapshot 必须能证明：

```text
这次训练当时用的 Ground Truth 到底是什么。
```

### 8.2 Snapshot 与源数据

Snapshot 是 immutable contract，不是源数据副本的唯一来源。

Training bundle 仍需要独立复制图像和生成标签文件，防止训练进程修改源素材。

## 9. SQLite Migration

`annotations.sqlite3` 新字段：

```text
scope_json TEXT NOT NULL DEFAULT '[]'
```

迁移策略：

```text
CREATE TABLE IF NOT EXISTS
    ↓
PRAGMA table_info
    ↓
if scope_json missing:
    ALTER TABLE ADD COLUMN
```

禁止：

- 删除 annotations.sqlite3；
- 新建空 DB 替换旧 DB；
- 重新编号 image_id；
- 批量重写历史 annotation version；
- 因 migration 失败静默回退到空标注。

## 10. Annotation → Material Projection

保存正式标注后，AnnotationRepository 可同步 MaterialRepository：

```text
annotation_state
annotation_scope
annotation_hash
annotated
box_count
labels
```

设计原则：

```text
AnnotationRepository = authority
MaterialRepository = projection
```

未来若出现跨库事务一致性问题，应考虑 transaction/outbox/reconciliation，不要反过来把 Material payload 当 Ground Truth。

## 11. 测试合同

必须至少覆盖：

### Duplicate

- same SHA + same GT → canonicalize；
- same SHA + different box → conflict；
- stable code same + class_id different → same GT；
- normalized bbox difference → conflict；
- legacy no scope + inferred new scope → compatible；
- explicit Train/Test same SHA → leakage error。

### Component

- same group stays together；
- group/video transitive union；
- file identity stays together；
- same camera + same session stays together；
- same camera + different session does not automatically union。

### Annotation State

- annotated + boxes → valid；
- confirmed_empty + scope + no boxes → valid；
- legacy confirmed_empty without scope → compatible global scope；
- unannotated → invalid training input。

### Migration / Snapshot

- old annotation DB migrates without data loss；
- scope changes annotation digest/version；
- material projection receives scope/hash；
- Snapshot v3 locks scope/hash；
- duplicate exclusions are auditable in Snapshot。

## 12. 第二批接口边界：Task Runtime Fencing

第一批完成后，下一优先级不是继续增加训练 UI，而是 Task Runtime。

### 12.1 已知风险

当前 Scheduler heartbeat thread 在 lease owner 丢失时可以退出，但 handler / child process 可能继续执行。

TaskRepository 又可能把过期 RUNNING task 重新 QUEUED。

潜在结果：

```text
Worker A lease lost
A child process still alive
    ↓
Task requeued
    ↓
Worker B claims
    ↓
A + B duplicate side effects
```

### 12.2 下一批应实现

WorkerContext 建议增加：

```text
execution_generation
lease_lost_event
cancel_event
assert_current_execution()
```

Repository 所有关键 mutation：

```text
heartbeat
checkpoint
finish
artifact publication
process identity update
```

必须校验：

```text
task_id
lease owner
generation/fencing token
```

失去 lease 时：

```text
set lease_lost
    ↓
handler stops accepting side effects
    ↓
terminate process tree
    ↓
old generation cannot finish task
```

Recovery：

- 检查 persisted PID；
- 检查 create_time；
- 检查 command hash；
- 旧进程仍存活时必须 adopt / terminate / fail closed；
- 不得直接启动第二个 child process。

### 12.3 ProcessController

Training 已有较强 process identity 基础，下一批应统一到：

- Training；
- Conversion；
- external tools；
- future Evaluation Worker。

不要新增另一套进程终止实现。
