# 训练任务逐素材选择设计

## 目标

创建算法训练任务时，不再把“数据集”当成训练选择单位。用户直接选择本次参与训练的图片素材，标签仅用于筛选素材。最终训练、验证和试验名单必须由后台写入不可变快照，可追溯且不能发生数据泄漏。

## 交互规则

- 每次打开训练任务弹窗，训练素材和独立试验素材默认均为空。
- 候选素材限定为已处理且已标注、文件仍真实存在的图片。
- 支持按文件名搜索，按一个或多个标签筛选；多标签采用 OR 语义，命中任意一个标签即显示。
- 支持逐张勾选、选择当前筛选结果、反选当前筛选结果、全选全部候选、全部不选。
- 随机试验集模式只维护一个训练候选池；后台先从候选池随机抽取试验集，再从剩余素材抽取验证集。
- 独立试验集模式分别维护训练素材和试验素材，两者不能重叠；验证集从训练素材中抽取。
- 页面允许保持零选择；提交时必须明确提示没有可训练素材，不能创建空任务。
- 28,898 张素材场景下，选择器只分页渲染当前页缩略图；全选等操作在 ID 集合上执行，不一次性创建全部 DOM。

## 数据合同

训练请求升级为逐素材合同：

- `split_mode`: `random_test_from_training_pool` 或 `independent_test_set`。
- `train_image_ids`: 用户明确勾选的训练候选素材 ID。
- `test_image_ids`: 独立试验模式下用户明确勾选的试验素材 ID；随机模式必须为空。
- `experiment_percent`: 随机试验模式的抽取比例。
- `validation_percent`: 从非试验训练候选中抽取验证集的比例。

旧的 `train_dataset_ids` / `test_dataset_ids` 只用于识别并拒绝错误的新请求，不再作为新版页面的选择合同。后台不得把图片 ID 扩展为同数据集的其他图片。

## 后台处理

后台 Worker 根据请求中的图片 ID 从项目素材索引精确取样。不存在、重复、未处理、未标注或文件缺失的素材都会使任务失败并给出明确原因。划分继续按来源组、内容哈希和文件身份进行防泄漏检查；随机种子、最终 train/validation/test ID、数量、比例和来源写入快照与任务详情。

## 异常规则

- 随机模式没有选择素材：拒绝提交。
- 独立模式训练或试验任一侧为空：拒绝提交。
- 训练素材与独立试验素材重叠：拒绝提交。
- 按来源分组后不足以形成所需角色：后台任务失败并明确说明，而不是偷偷复制素材。
- 用户选择后素材被删除或状态改变：后台以执行时真实状态校验并失败，前端刷新后可重新选择。

## 验收

- 前端载荷只包含用户实际勾选的素材 ID。
- 全选、全不选、按筛选全选和反选均不会把不可见的错误素材带入任务。
- 后台快照中所有 ID 都属于请求 ID；独立试验素材与训练/验证无交集。
- 刷新页面不会改变已经创建任务的快照。
- 前端、API、任务记录和快照数量一致。
