# 安全 AI 推理并发实施计划

> 使用 subagent-driven-development 执行独立任务，统一审查后提交。

**目标：** 在冻结模型配置、Worker Lease、CandidateStore 与正式 GT 安全边界内，支持有证据的双实例并发和跨 Provider 配额隔离。

**架构：** 延用现有 TaskRepository/调度数据库，增加推理资源许可与限流域状态，网络调用不占数据库事务；CandidateStore 仍由执行器主线程写入。历史配置、未知容量及未验证网关保持串行。并发结果按 image_id 持久化，恢复按已保存集合而非完成顺序。

**技术栈：** Python/FastAPI、SQLite WAL、原生 JS、现有 requests Provider 与统一 Worker。

## 任务与验收

- [x] 审计并冻结策略：容量证据绑定配置、等价模型、原生路由；配置变更使证据失效；默认并发 1；复用原模型配置弹窗与连接/真实图片测试。
- [x] Provider 兼容：保留三种请求合同；区分鉴权、协议、额度、临时限流和暂时服务故障；携带脱敏追踪信息与 Retry-After，禁止跨模型回退。
- [x] 现有任务库资源许可：跨任务/进程并发上限、作用域隔离、共享冷却、崩溃到期回收、取消与租约栅栏；不建立新数据库或调度服务。
- [x] 统一执行器：有界窗口、主线程短事务写候选、乱序恢复、成功/空目标不重做、取消后迟到结果丢弃、确定性错误快停、有界重试与总时长。
- [x] 有效验收：两个独立 HTTP 实例重叠处理；单实例及历史配置串行；跨 Provider、共享配额、取消/恢复/失租、GT 不变；既有坐标回归复用。
- [x] 汇总运行指标与现场只读验证模板，明确自动化模拟与 4070 现场未验证的区别。
- [ ] 更新版本、专项需求/设计/验证与交接文档；检查远端快进，正常提交推送，核对精确 SHA 的 CI。

## 责任边界

Provider 独立任务仅修改 providers 与对应测试；配置能力任务负责策略/证据及现有配置 API/前端；主任务负责执行器、CandidateStore 恢复、TaskRepository 资源许可与综合验收。所有任务禁止操作生产、提交和推送，由主任务统一审查和发布。

## 实质限制

4070 是无法访问的内网环境，不修改启动服务、不推断 GPU 容量、不宣称现场验证。远端基线 42.24.552 / 34a287efee0d1f35fb9e818fb90acb898f00dad1，已有审核/素材库/ZIP 能力保持原有所有权。
