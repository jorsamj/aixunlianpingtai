# 2026-11-09｜42.24.565 AI 自动标注任务详情 UI/UX 与完整错误导出

## 需求与范围

- 用户反馈：AI 标注任务详情层次混乱；失败图片把模型标签、原生查询、原始响应等全部直接展开，错误多时难以阅读；原“导出本页错误”只能获取当前页，无法交付一份完整问题清单。
- 本轮仅修改 `static/app.js` 中原有 v60 任务详情 Owner、`static/styles.css`、针对性前端测试和静态资源缓存版本。复用原 CandidateStore 和 `/api/v60/projects/{project_id}/annotation-tasks/{task_id}/candidates?filter=failed`，不增加 API、缓存、任务系统、数据写入、重试副作用。
- 不改 WeVisOne 原生推理协议、检测框和坐标、审核/GT、零框成功判定，不访问生产服务器或重启模型。

## 原因与设计决策

1. 原详情用 `wait427-anim` 动画块、紧凑计数、零散 `alert` 和操作按钮平铺信息，无法建立“任务概况 / 异常 / 操作”的视觉主次。原逐图 HTML 对每个错误直接渲染 11 项技术证据，导致大量长卡片。
2. 原 `loadAiFailureDetails60` 每次只请求 `limit=50`，导出按钮直接传 `result.items` 给 `aiFailureExport60`，只能导出正在看的 50 张或更少。
3. 服务端 `CandidateStore.read_page` 已按 `status='failed'` 支持分页游标、总数和 `review_revision`；复用它每次读 100 张，可累计本任务全部失败候选。原数据一经重试可能变化，因此必须每页检查 `total/review_revision`、图像 ID 唯一性和下一页游标，且最终条数恰好等于初始总数。不一致时禁止生成“完整导出”文件。

## 实现结果

| 项目 | 修复前 | 本版行为 |
| --- | --- | --- |
| 任务概况 | 大面积跳动动画与信息平铺 | 紧凑状态、真实进度条、四个独立数据指标、当前图片；任务状态按风险分色 |
| 全局错误 | 与进度和卡片混在一起 | 简明异常提示与处理入口；可继续执行审核/差量重试等原有操作 |
| 逐图详情 | 每条直接展示全部原始证据 | 缩略图、文件名、错误码、HTTP、原因和建议优先；`details` 按需展开原始标签、请求追踪、结构摘要、历史失败证据 |
| 失败分页 | 50 张一页、仅有下一页 | 12 张一页，上一页/下一页，当前位置和总数明确，减少视觉噪声 |
| 错误导出 | CSV/JSON 均只导出当前页 | CSV/JSON 都按后台游标遍历**全部失败图片**，显示读取进度，可取消；发生修订、重复、漏页或请求失败时不生成不完整文件 |
| 历史证据 | CSV 数组对象通过 `.join` 变成 `[object Object]` | 复杂数组使用 JSON 保留每次尝试的错误信息；原 CSV 公式注入转义继续保留 |
| 生命周期 | 多次页请求存在旧结果覆盖风险 | 详情请求序号隔离迟到页；关闭弹窗中止导出；任务终态仅在第一页且未导出时刷新错误列表 |
