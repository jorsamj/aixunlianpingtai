# 算法综合报告 UI/性能与弹窗滚动专项（2026-11-12）

## 审计结论

- 旧算法综合报告由 `static/app.js:algorithmReport429` 的整块 HTML 模板直接生成；深色大头图、密集 KPI、单条 mAP50 曲线与全量历史任务 DOM 不利于快速查阅。
- `app.py:v49_algorithm_report` 在逐条训练任务循环中调用 `_v49_job_label_counts`；项目 Snapshot 缺失时会回退到当前可变标注，可能触发每个训练任务数万张图片的历史查询，既慢又存在历史口径污染风险。
- 基础弹窗和动态栈弹窗共用 `.modal` / `.modal-card` / `.modal-body`；各历史 CSS 层存在 `height:auto`、`max-height` 和 `place-items:center` 组合，异步内容变化可能让内容区无法形成稳定滚动容器。
- 线上“弹窗偶发居中、无法下滑”的真实触发链与比例**尚未通过浏览器复现**；本轮是针对已经确认的 CSS 结构风险的最小修正，不宣称生产根因完全排除。

## 本轮修改

1. 综合报告 API 增加可选 `lightweight=true`；旧无参接口行为保留。轻量模式不再遍历每个历史任务的当前素材标注统计类别数量；原任务身份、耗时、状态、历史趋势保留。
2. 已有算法版本元数据派生最近 40 个版本的 Val、独立 Test mAP50（有可信 Test 才展示）、冻结 Snapshot 身份及当前版本、最佳版本摘要；不根据 mAP 推断业务准确率，不直接比较不同 Test 基准。
3. 综合报告默认首屏只显示算法信息、Val/Test/历史最佳/版本变化和最近最多 30 条有指标的曲线点，版本对比、数据证据和训练任务面板切换后才渲染；训练记录限制展示最近 20 项，原后端仍保留完整计数和数据入口。
4. 白底低装饰的紧凑布局，统一字体、浅边框、间距、响应式表格；Tab 支持键盘方向键，浏览器反馈按需展示。
5. 报告在点击后即显示可关闭的加载窗口，异步返回使用原 `ModalContentRuntime.captureOwner()`，关窗、换项目或打开新窗口后不会向旧弹窗回填；单请求 20 秒中止，超时真实提示，不通过增加长等待掩盖卡顿。
6. 公用弹窗视觉约束修复：弹窗卡片与内容区 `min-height:0`，明确头部固定/内容可滚动、`overscroll-behavior:contain`、稳定滚动条；综合报告独立限定视口高度，原训练报告专属 `86dvh` 规则不覆盖，不重写中央弹窗 Owner。
7. 新增 Node 展示/契约测试、API lightweight 性能回归和 Playwright 真实弹窗回归（桌面/窄屏、反复打开、切换 Tab、关闭后延迟响应）。

## 边界与必须后续验收

- 未修改训练、Worker、冻结 GT、原评测任务、转模型、生产数据、存储回收机制及现有普通报告数据来源。
- 轻量算法综合报告不再显示“各训练任务累计标签框数”。在没有可信历史冻结统计时明确标注“快速模式未汇总”，需要看具体版本应进入单版本报告。不能把当前可变标注重统计伪装为历史真值。
- 此轮未实测 A800 上 API P50/P95、页面主线程长任务和物理滚动，也未执行真实 Chrome 截图审美验收。禁止承诺某个毫秒数或“已彻底不卡”。
- 验收检查：`/api/v49/projects/.../algorithms/.../report?lightweight=true` HTTP 200、响应耗时与返回量、四 Tab 切换、1920/1366/390 分辨率、滚动容器边界、连续多次打开关闭、快速切项目/关窗、真实历史版本的 Val/Test 口径、没有 Snapshot 的历史任务、CI。
- 代码仅提交到长期开发分支 `feature/external-algorithm-publishing`；未部署 A800 或 4070、未重启服务、未修改磁盘数据。
