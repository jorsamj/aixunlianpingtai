## 已收口 P0

### P0-01 Duplicate / Leakage Component

`platform_core/training_splits.py` 现在会在任何随机切分前按 `content_sha256`、来源 group / 视频 group、file identity 建立传递闭包 leakage component。

- exact duplicate + 本次 selected-label GT 相同：稳定 canonical dedupe，其他记录写入 exclusion。
- exact duplicate + 本次 selected-label GT 不同：切分前 fail-closed，不再 keep-first。
- Independent Train/Test 若 SHA、来源组或 file identity 落入同一 component，直接阻断。
- 最终 `_assert_no_leakage()` 继续作为最后防线。
- `training_labels.py` 又把 duplicate GT fencing 前移到 durable TRAINING task 创建前；用户不再需要等 Worker 启动后才看到同类冲突。

定向测试已覆盖 split duplicate/conflict、training-label pre-task fencing。GitHub Actions 已在 Windows/Ubuntu 多次跑通过相关测试；真实 10k/20k 数据规模性能仍需服务器验收。

### P0-02 Empty boxes 不得自动变 confirmed_empty

`platform_core/annotation_repository.py` 默认规则已改为：有 boxes -> `annotated`；无 boxes 且没有显式状态 -> `unannotated`。

只有人工确认、可信导入等显式调用方才能写 `confirmed_empty`，并且必须带正确 annotation scope。定向测试已纳入 P0 CI。

### P0-03 Rollback 指针接入真实训练基线

`TrainingHandler` 调 `choose_iteration_base()` 时已经显式传入 `algorithm['current_version_id']`。回滚 V5 -> V3 后，下一次迭代必须从 V3 的 verified train checkpoint 开始；当前版本不可训练时返回 `CURRENT_VERSION_UNAVAILABLE`，不会偷偷换成 V5、其他历史版本或母模型。

`tests/unit/test_algorithms.py` 已覆盖“显式 current version 优先”和“current version 不存在 fail-closed”。

### P0-04 algorithms.json 跨进程 mutation fence

`platform_core/algorithms.py` 已加入：

- Windows/POSIX 跨进程 file lock；
- 原子写文件；
- per-algorithm `revision`；
- expected_revision 冲突检测；
- version attach 按 task_id 幂等；
- rollback 只移动 current pointer，不改写历史版本。

这已解决原先仅有进程内 `threading.RLock` 的明显丢更新风险。长期仍建议把算法版本元数据迁入事务型数据库，但当前 JSON 路径已经具备基本多 Worker 写安全。

## 新增收口项

### Worker 角色隔离

旧 `task_worker.py --roles all` 会让 import / annotation / video / training / conversion 等长任务共享一个串行执行循环。当前实现改为 supervisor 监督多个 role worker，避免大导入把训练或转换长时间堵住。

子 Worker 使用统一 process identity（PID、create_time、command hash、process group、launch token）管理；父进程退出时使用 `ProcessController` 安全终止对应进程树。

### Deployment Test 子进程生命周期

部署测试已从裸 `subprocess.Popen()` 路径收口到 durable process identity：

- 启动后绑定进程身份；
- 运行中 heartbeat；
- Cancel 终止完整进程树；
- lease/DB 异常时不允许留下无主推理进程；
- recovery 只处理身份验证通过的旧进程；
- 已存在且验证通过的结果可恢复提交，不无脑重复推理。

`.rknn/.om/.bmodel` 在无真实板卡/runtime 时继续明确标记硬件阻断，不把“转换成功”和“板端验证成功”混成一个状态。

### Training Version Artifact Manifest

新训练版本发布时，如果模型来自标准 task artifact 目录，`attach_version()` 会读取该任务的 `snapshot.json` / `payload.json`，冻结：

- 模型文件名、size、SHA256；
- framework / task type / input size；
- snapshot_id / parent_version_id；
- num_classes / names；
- stable `label_id`、业务 code、platform class id、task-local YOLO class id；
- manifest 自身 SHA256。

下一次严格迭代选择版本时会核对模型文件 size/SHA，模型被替换或损坏则 fail-closed。

`tests/unit/test_algorithm_artifact_manifest.py` 已新增，覆盖 manifest 生成、模型篡改阻断、snapshot_id 错配阻断、同 task_id 幂等 replay。当前最新 GitHub Actions 中 Ubuntu 已通过；本文件更新时 Windows job 仍在执行，因此 Windows 本轮结果暂不标记完成。

## 真实 Linux/A800 验收边界

GitHub Actions 只能验证代码路径，不等于生产验收。真实 A800 至少还要验证：

- `actual_device` 真正为分配的 A800；
- RAM/SHM guard 在真实 DataLoader worker 数下有效；
- 训练前后源素材 SHA 不变化；
- Train/Validation 运行期间 Test 未物化；
- best 固定后才访问 Test；
- post-processing crash/restart 不会重复训练；
- rollback 后下一次训练实际加载被回滚版本；
- Artifact Manifest 中模型 SHA 与真实 best.pt 一致；
- 10k/20k 真实素材下 split、bundle、任务刷新和导入耗时可接受。

100k 做有界架构验证；百万级未压测前保持“未验证”。
