## ChatGPT 已修复（代码已提交，尚待本地/CI/服务器验证）

### P0-01 Duplicate / Leakage Component：核心 split 根因已修

`platform_core/training_splits.py` 已改为：

1. 在任何随机切分前，先按 `content_sha256`、来源 group / 视频 group、file identity 建立传递闭包 leakage component。
2. exact duplicate + 本次 selected-label GT 相同：只保留稳定 canonical image_id，其余写入 `exclusions=exact_duplicate_of:<id>`。
3. exact duplicate + 本次 selected-label GT 不同：在切分前直接抛出 `duplicate annotation conflict`，不再 keep-first。
4. independent Train/Test 请求若 content SHA 已重叠，切分前直接阻断；若来源组/file identity 落在同一 component，也直接阻断。
5. 最终 `_assert_no_leakage()` 继续作为 fail-closed guard。
6. manifest 增加 `duplicate_content_group_count` 和 `deduplicated_image_count` 统计。

对应测试已补到 `tests/unit/test_training_splits.py`，覆盖：显式 Train/Test SHA 重叠、相同 GT exact duplicate canonical dedupe、不同 GT duplicate conflict。

**未验证：** 当前 GitHub 分支没有 CI 状态；上述测试尚未在用户 Windows 环境和 Linux/A800 环境实际运行。因此只能标记“代码已修，待验证”，不能标记“验收通过”。

**仍需补一层：** HTTP `/api/v63/.../training-preflight` 目前仍主要是投影检查。后续要让它在创建 durable training task 之前复用同一 split integrity 逻辑，直接展示 duplicate/conflict/exclusion 的准确数量。Worker 侧根因已收口，但前端预检体验还未完全闭环。

### P0-02 空 boxes 误判 confirmed_empty：已修

`platform_core/annotation_repository.py` 已把默认状态从：

```python
'annotated' if boxes else 'confirmed_empty'
```

改为：

```python
'annotated' if boxes else 'unannotated'
```

现在只有调用方明确传入 `annotation_state='confirmed_empty'` 才能写已确认负样本。可信 YOLO 空 TXT / 人工确认负样本仍应显式携带正确 `annotation_scope`。

对应新增 `tests/unit/test_annotation_repository.py`，覆盖默认空 boxes -> `unannotated`，以及显式 `confirmed_empty + scope`。

**未验证：** 尚未实际运行测试；需要 Codex/人工在拉取最新分支后执行最小定向测试。

## 当前仍未闭环的 P0

### P0-03 回滚指针尚未接到真实训练基线

`algorithms.py` 已新增 `current_version_id`、rollback 和 `choose_iteration_base(... current_version_id=...)`，但 `TrainingHandler` 当前调用 `choose_iteration_base()` 时没有传 `algorithm['current_version_id']`。

目标：回滚 V5 -> V3 后，下一次迭代训练必须从 V3 的 verified train checkpoint 开始；若当前指针不可训练，明确 `CURRENT_VERSION_UNAVAILABLE`，不得偷偷用 V5、其他历史版本或母模型。

建议最小修复点：`platform_core/training_tasks.py` 中真实 TrainingHandler 选择 base 的唯一调用处显式传：

```python
current_version_id=str(algorithm.get("current_version_id") or "") or None,
```

并在 `tests/unit/test_algorithms.py` 增加“V5 最新、current=V3 时必须选择 V3”的测试；还要验证当前版本不可训练时明确失败。

### P0-04 algorithms.json 并发安全仍不足

当前 `_ALGORITHM_WRITE_LOCK` 只是单 Python 进程内 `threading.RLock`。多 Worker / 多进程仍可能 read-modify-write 丢版本。

目标：至少改为跨进程 file lock + revision/CAS；长期建议算法版本元数据迁入 SQLite/PostgreSQL 事务。不能把当前 RLock 当成并发问题已解决。
