## 当前已确认 P0 缺口

### P0-01 Duplicate / Leakage Component 仍未从根上闭环

当前 `training_splits.py` 仍以来源 group 先随机切分，再用 `_assert_no_leakage()` 检查 content SHA。这样相同内容、不同 image_id 的记录仍可能先被分到不同 role，再报 `content hash leakage`。

目标：

1. 切分前建立 leakage component，至少联合 `content_sha256`、来源 group、视频 group、file identity；支持传递闭包。
2. exact duplicate + selected-label GT 相同：canonical dedupe，只保留一个训练样本，并把其余记录写入 exclusions。
3. exact duplicate + selected-label GT 不同：明确 `DUPLICATE_ANNOTATION_CONFLICT`，不得“keep first”。
4. independent Train/Test 在请求阶段若落入同一 component，直接阻断。
5. 最终 `_assert_no_leakage()` 继续保留为 fail-closed guard。
6. HTTP preflight 最终也要在创建 durable training task 前展示准确 duplicate/conflict/exclusion 数量，而不是只由 Worker 在 2% 阶段发现。

### P0-02 空 boxes 仍可能被误判 confirmed_empty

`AnnotationRepository.upsert_many()` 当前默认：

```python
default_state = row.get('annotation_state') or ('annotated' if boxes else 'confirmed_empty')
```

这会把“调用方没有显式状态 + boxes=[]”自动变成已确认负样本。

目标：默认必须是：

```python
'annotated' if boxes else 'unannotated'
```

只有人工明确确认或可信外部数据集的空 TXT/明确负样本合同，才允许写 `confirmed_empty`，且必须带正确 `annotation_scope`。

### P0-03 回滚指针尚未接到真实训练基线

`algorithms.py` 已新增 `current_version_id`、rollback 和 `choose_iteration_base(... current_version_id=...)`，但 `TrainingHandler` 当前调用 `choose_iteration_base()` 时没有传 `algorithm['current_version_id']`。

目标：回滚 V5 -> V3 后，下一次迭代训练必须从 V3 的 verified train checkpoint 开始；若当前指针不可训练，明确 `CURRENT_VERSION_UNAVAILABLE`，不得偷偷用 V5、其他历史版本或母模型。

### P0-04 algorithms.json 并发安全仍不足

当前 `_ALGORITHM_WRITE_LOCK` 只是单 Python 进程内 `threading.RLock`。多 Worker / 多进程仍可能 read-modify-write 丢版本。

目标：至少改为跨进程 file lock + revision/CAS；长期建议算法版本元数据迁入 SQLite/PostgreSQL 事务。不能把当前 RLock 当成并发问题已解决。
