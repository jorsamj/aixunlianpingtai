## 已收口 P0

### P0-01 Duplicate / Leakage Component

`platform_core/training_splits.py` 在随机切分前按 `content_sha256`、来源 group / 视频 group、file identity 建立 leakage component：

- exact duplicate + 本次 selected-label GT 相同：稳定 canonical dedupe；
- exact duplicate + 本次 selected-label GT 不同：切分前 fail-closed；
- independent Train/Test 若 SHA、来源组或 file identity 落入同一 component：直接阻断；
- 最终 `_assert_no_leakage()` 继续作为最后防线。

`training_labels.py` 又把 duplicate GT fencing 前移到 durable TRAINING task 创建前。定向 CI 已有成功记录。真实 10k/20k 数据规模性能仍需 A800 服务器验收。

### P0-02 Empty boxes 不得自动变 confirmed_empty

`platform_core/annotation_repository.py` 默认规则已改为：有 boxes -> `annotated`；无 boxes 且没有显式状态 -> `unannotated`。只有人工确认、可信导入等显式路径才能写 `confirmed_empty`，且必须带正确 annotation scope。

### P0-03 Rollback 指针接入真实训练基线

`TrainingHandler` 调 `choose_iteration_base()` 时显式传入 `algorithm['current_version_id']`。回滚 V5 -> V3 后，下一次迭代必须从 V3 的 verified train checkpoint 开始；当前版本不可训练时返回 `CURRENT_VERSION_UNAVAILABLE`，不会静默切换到 V5、其他历史版本或母模型。

### P0-04 algorithms.json 跨进程 mutation fence

`platform_core/algorithms.py` 已加入 Windows/POSIX 跨进程 file lock、原子写、per-algorithm revision、expected_revision 冲突检测、同 task_id version attach 幂等，以及只移动 current pointer 的 rollback。

长期仍建议将算法版本元数据迁入事务型数据库，但当前 JSON 路径已具备基本多 Worker 写安全。

### P0-05 Training Version Artifact Manifest

新训练版本会冻结模型文件 size/SHA256、framework/task/input size、snapshot/parent lineage、num_classes/names、stable label IDs 与 task-local YOLO IDs。严格迭代选择会校验 manifest 自身 hash、模型 hash、snapshot/parent 对应关系和父模型 lineage。代码/CI 层已有成功记录；真实 A800 best.pt 一致性仍需服务器验收。

### P0-06 Generic Retry Attempt Audit

Generic retry 创建新的 task_id，`retry_of` 指向上一 attempt，旧 terminal task 不被覆盖；MATERIAL_BATCH 会用 SQLite backup 克隆冻结 selection，只重试失败行；POST_PROCESSING_FAILED 继续走专用后处理重试。

原来 `platform_core.task_runtime` 包导出 audited repository，但 `platform_core.task_runtime.repository.TaskRepository` 仍保留旧 same-row retry，存在直接 import 绕过风险。当前 `audited_repository.py` 增加兼容 fence：包初始化时把 core repository 的 `retry` 绑定到 audited immutable-attempt 实现，因此直接 import 也不能恢复旧语义。新增回归测试直接实例化 core import，并验证 retry 生成新 task_id、保留旧失败行和复制 payload。

GitHub Actions run `34485727739` 的 Ubuntu 3.12 已实际完成 compile + targeted P0 tests，结论 `success`。Windows 当前不作为阻塞条件。长期代码清理仍可把 audited retry 正式内聚回 core module，移除兼容 monkey-patch，但这已降为维护项，不再是运行时双语义 P0。

### P0-07 Annotation Ground Truth / Stable Label Authority

训练语义只有一个 Ground Truth 权威来源：`AnnotationRepository`。

- `label_id` 是类别永久语义身份；旧 code / class_id 是投影。
- 已有合法 stable `label_id` 时，写入会按当前 schema 修正陈旧 code/class projection。
- 未知 `label_id`、未知 annotation scope 或缺失类别身份的正式写入 fail-closed。
- AI 标注人工审核冻结 `review-scope.json`，审核通过后把实际检查过的 stable IDs 合并到正式 `annotation_scope`。
- 素材层 `labels/label_ids` 不能单独让类别进入训练；反向地，素材 tag 缺失但 AnnotationRepository 有合法 GT 时仍可训练。

关键提交包含 `6ed125f`、`677224a`、`b11db68`、`db1499c`、`0415a55`。定向 Ubuntu CI 已有成功记录。

### P0-08 AI Intervention Immutable Snapshot

旧 `train_worker.py` 中 `_master_unused_counts()`、`_box_to_yolo_worker()`、`_supplement_snapshot()` 已删除，不再允许训练进程读取项目全局 `images.json/annotations/uploads` 后动态改 split 或把新素材塞入当前 bundle。

当前 AI 动作规范为：

- `continue`：原冻结数据继续训练；
- `extend_epochs`：只在同一 `args.data` / 同一 snapshot 上追加轮次；
- `recommend_supplement`：只保存为 `ai_next_task_recommendation`，供下一次新训练任务使用，不修改当前训练数据。

历史模型若仍返回 `supplement_and_retrain`，平台会强制转换成 `recommend_supplement`。即使用户自定义旧 prompt，平台也会追加强制 immutable-snapshot 执行约束。

关键提交：`d751121`、`2b3f549`、`f6bc871`。GitHub Actions run `34484244735` 的 Ubuntu 3.12 compile 与 targeted P0 tests 已完成 `success`。真实 A800 上实际启用 AI intervention 的长训练仍未验证。

### P0-09 Conversion Lifecycle / Artifact Integrity

Conversion Worker 已使用 durable ProcessIdentity：启动绑定 PID/create_time/command hash/process group/launch token，持续 heartbeat；Cancel 终止完整进程树；Recovery 只处理身份验证通过的旧进程，不能因 PID 复用误杀无关进程。

状态语义明确拆开：

- 转换产物成功生成：转换任务可为 `SUCCEEDED`；
- RKNN/OM/BMODEL/TensorRT 等目标没有真实板端/runtime 验证时：`board_validation_status=pending`，不把“板端验证成功”伪装成转换成功条件；
- SDK/工具缺失：`BLOCKED_BY_ENVIRONMENT`；
- 用户取消：`CANCELLED`。

新增成功发布完整性 gate：即使 `job.json` 已写 `status=done`，Worker/recovery 也不能直接相信。必须重新验证 `artifacts/manifest.json` 位于当前任务目录、schema/job_id/target 一致，并逐个验证真实 output 存在、size 一致、SHA256 一致。任一产物缺失、被替换或路径越界，任务转为 `FAILED + CONVERSION_ARTIFACT_VERIFICATION_FAILED`，不得假成功。

关键提交：`9ddccab`、`3db4552`。GitHub Actions run `34485031604` 的 Ubuntu 3.12 compile 与包含新增转换完整性测试的 targeted P0 tests 已实际完成 `success`。真实 RKNN/Ascend/Sophon/TensorRT 工具链和板端验收仍按对应硬件环境分别执行。

## 其他已收口项

### Worker 角色隔离

旧 `task_worker.py --roles all` 会让 import / annotation / video / training / conversion 等长任务共享一个串行 Scheduler。当前实现为 supervisor + 独立 role worker，各角色拥有独立执行通道。子 Worker 使用统一 process identity 管理。

### Deployment Test 子进程生命周期

部署测试已从裸 `subprocess.Popen()` 收口到 durable process identity：启动后绑定进程身份、运行中 heartbeat、Cancel 终止完整进程树、recovery 只处理身份验证通过的旧进程。`.rknn/.om/.bmodel` 无真实板卡/runtime 时明确标记无法执行真实板端测试。

## 当前仍未闭环的 P0 / P1

- **API Security（生产前 P0）**：当前 `train_servers.json` 仍存在 plaintext API Key 路径，GET 可能直接返回 key；CORS 仍是通配 origins + credentials；可配置 remote/model URL 仍需统一 SSRF 防护。
- **ZIP/YOLO 大规模导入（P0/P1）**：10k/50k/100k 需验证真正 worker 化、一次扫描、批量 SQL、避免重复 SHA/解码；历史 10k ZIP 导入曾出现单核 Uvicorn 长时间占用。
- **全局存储治理（P1）**：source/cache/bundle/runs/artifacts/conversions quota、retention、GC 尚未完成。
- **Material projection（P1）**：训练 GT 已与 Material tags 隔离，但 Annotation -> Material projection 的事务原子性/reconcile 仍需治理。
- **MaterialRepository 查询技术债（P1）**：`%LIKE%`、JSON extract、legacy full-row mutate/monkey-patch 路径需继续收敛。
- **Split 性能（P1）**：`_select_grouped()` subset-sum 在大量单元素 group 时的 CPU 复杂度需 10k/20k 实测，100k 前确认不退化。
- **Audited retry 代码结构（P1）**：运行时双语义已被 compatibility fence 阻断；后续可把实现内聚进 core repository，移除 monkey-patch。

## 真实 Linux/A800 验收边界

GitHub Actions 只能验证代码路径，不等于生产验收。真实 A800 至少还要验证：

- `actual_device` 真正为 scheduler 分配的 A800；
- RAM/SHM guard 在真实 DataLoader worker 数下有效；
- 训练前后源素材 SHA 不变化；
- Train/Validation 运行期间 Test 未物化；
- best 固定后才访问 Test；
- post-processing crash/restart 不会重复训练；
- rollback 后下一次训练实际加载被回滚版本；
- Artifact Manifest 中模型 SHA 与真实 best.pt 一致；
- generic retry 创建独立 task_id，旧失败行、日志、错误和结束时间不被覆盖；
- MATERIAL_BATCH retry 只重试 failed rows；
- 训练标签来自冻结 Annotation GT，而不是素材 tag / 当前项目 class index；
- AI intervention 不修改当前 snapshot；
- 10k/20k 真实素材下 split、bundle、任务刷新和导入耗时可接受。

100k 做有界架构验证；百万级未压测前保持“未验证”。
